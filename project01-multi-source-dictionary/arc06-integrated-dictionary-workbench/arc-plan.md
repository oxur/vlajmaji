## Architecture and runtime boundaries

Four PackIds and `CollectionSelection::All` remain unchanged. A live journal and optional sealed owned package are separate inputs. S01 NEW-root publication is a rebuildable view, not authoritative edit storage and not cross-file SQLite atomicity. A configured same-home refresh/active pointer belongs to S02 with explicit version/concurrency design.

Full typed/source/seal/context verification occurs on explicit build/refresh/check boundaries. Ordinary querying reads its prepared store using existing unverified typed provider/index setup, then checks small captured upstream/owned identities before and after each operation. It does not reconstruct complete histories, reread original release files, fingerprint all descriptors or clone/materialize the whole Dictionary per query. Freshness is operational identity, not authentication of arbitrary hostile raw SQL changes. Explicit verification retains that separate role.

Curated contexts must come from selected installed sealed pack bodies. A one-pack binding supplies the ORIGINAL loaded Dictionary directly; composing even a singleton can normalize/deduplicate metadata and change the pinned hash. Multi-pack bindings explicitly declare order and use the existing composition function. Missing binding is existing Unavailable/Unresolved, incorrect binding is typed failure; updates never rewrite an old pin. Curation and source contexts remain original authorities; derived composition has existing keyed equal collapse/unequal reject, anonymous notice/lineage dedup and extension maximum multiplicity.
