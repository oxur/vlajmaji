## Source-backed design decisions — provisional until accepted S04

**One parser, no legacy identity fabrication.** The intended narrow lexicon API is a pure `parse_see_also_tokens(notes: &str) -> Vec<SeeAlsoToken>`, with token fields `byte_start`, `byte_end`, `target_spelling`, `rule_version`. Exact public naming/derives/docs are finalized with the source allowance. Factor the SAME existing loop once; the old private `extract_see_also(origin, notes)` maps these tokens into its existing private-field `SourceCrossReference`, preserving origin, `field=notes`, empty initial targets, and every old span/rule/duplicate/math/boundary behavior. New typed callers attach actual ContextRecord/Assertion/SourceEvidence themselves. No RecordIdentity is manufactured from an EntryID; no archive, import, model schema or stored relation is created.

**Exact spelling target population.** Source-clause tokens resolve all exact matching retained Entry rows in the prepared admitted Dictionary, including entries with zero currently eligible assertions. Report every competing retained target, then separately project eligible hop assertions under selected source/release/head and requested-source rules. A retained target filtered from hops remains an explicit retained-but-not-traversable observation; it is not silently absent. This is the legacy all-captured-spelling rule on an IDENTICAL admitted captured/model population, not a claim that a selected workbench discovers every catalogue spelling. With different selected populations, the new operational universe is explicitly `admitted-retained-entry-exact-v1`. Absence means unresolved WITHIN that universe. Existing `reference_projection` accepts Local/Catalog identities, not spelling; it cannot truthfully supply catalogue-only clause targets. No new catalogue spelling scan/API or ordinary-open descriptor scan is implied. Actual typed RelationTarget::Catalog can reuse the accepted targeted S03 reference route and its truthful metadata-only observations.

**Publisher authority and distinct admission.** A source-backed relation uses the actual SourceEvidence owner (validated equal to the structural origin source). An editorial relation uses the actual referenced OwnedRevisionRecord.source, even when different from the origin's source. Other with neither uses an explicitly labelled `unattributed_origin_source` operational fallback, never a source/editorial attestation. A parsed clause uses its actual ContextRecord evidence/assertion source and remains derived parser evidence. Preserve kind, direction, scope, actual revision/evidence and both publisher/origin identities independently. Requested sources restrict BOTH publisher authority and every seed/from/hop assertion; cross-source/reverse edges cannot bypass either check. Stored relation retention does not invent an assertion/head eligibility field for RelationRecord itself; hop associations remain independently eligible.

**Derived traversal steps versus actual evidence.** A result step identifies `(evidence_identity, orientation, from_assertion_id)`; this is a DERIVED step namespace, not an actual RelationID/ContextID. Evidence identity is the real RelationID or `(ContextID, byte_start, byte_end, rule_version, exact target token)`. Each step retains its actual evidence identity/body and a complete ordered target-observation roster. One relation applicable to two actual from assertions yields two steps. Duplicate clause tokens at different spans remain different evidence identities. Separate counts name traversal steps, distinct evidence identities, and union-associated assertion IDs; none is labelled occurrences or faked as an assertion result. Exact DTOs/field names, order and page protocol remain near-issue work.

**Finite breadth-first traversal.** Seed actual eligible assertion occurrences at exact start spelling (empty spelling is not newly rejected). Allow depth only1/2. Forward uses origin→target; Reverse uses target→origin; Bidirectional emits both orientations; Unspecified uses structural origin→target while retaining original Unspecified. Role expansion uses actual Entry/Assertion/Form/Sense associations, then eligibility and source filters. Frontier nodes are actual assertion IDs, visited once at minimum depth; emit each exact directed step key once at its first depth, including bounded back/cycle observations, without re-expanding visited nodes. Unresolved/Unknown/catalogue-only/unverified observations supply no invented hop. A Reverse relation without an actual target-side hop node is not an outgoing step merely because its structural origin is seeded. Final format-local confirmed versus aggregate-unverified handling must be reconciled with accepted S03 lower resolver policies before issue; do not infer a common matcher.

**Record detail is not filtered query authentication.** Detail identifies actual stored RelationRecord or actual ContextRecord+token with typed content/view identity; it does not claim to reproduce a query-specific source-filtered traversal step. Choose complete all-current-view record detail and distinguish its target/admission roster from the step's requested-source-filtered observations. Same-view record keys remain valid across filters, analogously to S04 Form detail. A query-bound step page/cursor is a separate identity. No fake assertion/occurrence, public trusted-body setter or Full hydration for Compact/detail follows.
