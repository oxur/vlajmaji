## 1. Useful increment and preserved boundaries

A Rust caller or CLI can configure a named mixed selection in a distinct explicit file, choose a configured default, explicitly refresh that profile into a NEW immutable workbench root and publish that root as active, query the captured profile, and inspect prior prepared roots. An owned edit or upstream update makes a Head/current-generation view stale until explicit refresh; a historical owned revision is selected as such. Profile membership/default/removal/reload changes invalidate captured query identities. Old prepared roots and authoritative journal/catalogue rows are never overwritten or cleaned up.

This does not reinterpret existing `collections configure/default`, CollectionProfiles version1, `lookup`, `lookup-detail`, PackId/All-four, or the old global default store. The workbench configuration is a DIFFERENT format/kind, never an extra v1 field or a silently migrated `config.toml`. Every new command requires an explicit native `--config FILE`; omitting a profile selects that file's declared default, not a default filesystem location. Existing ambient-path resolution remains only on its unchanged old routes. No actual user configuration/default is consulted, even in validation. This is a routine concrete design choice within the activated workbench, not a new Operator setting question.

No normalized model, journal schema, snapshot format, linguistic policy, dependency, Cargo lock, new cache/worktree, workflow or existing core provider/projection change is intended. Current S03 owns complete integrated reference admission; S04/S05 own the other query variants. No source acquisition, retained Full leaf access, benchmark, cleanup, network or external delivery. Future functional Full and final composition gates keep their parent owners.

## 2. Distinct strict configuration and native paths

Use a caller-supplied JSON file, conventionally `workbench.json`, kind `vlajmaji-workbench-profiles`, version1. Strict duplicate keys at EVERY object nesting, unknown fields/kind/version and malformed native descriptors are rejected before referenced roots are opened. This is a new typed format, not canonical-JSON authenticity. Readers preserve exact captured bytes/hash; writers use a typed fixed-order serializer with one LF and make no general ordering claim for stdout Json(Value).

Exact top-level keys: `version,kind,revision,default_profile,profiles,prepared`. `revision` is a nonnegative u64 bounded to SQLite-compatible i64::MAX for consistent control inputs, incremented with checked_add on a semantic change; first committed file revision1. `default_profile` is nullable String. `profiles` is a vector sorted by valid unique name at serialization. Names are nonempty ASCII `[A-Za-z0-9_-]`, at most64 bytes; no whitespace, path components or implicit case folding.

Each profile has EXACT `name,catalogue_root,owned_root,selection,active_generation`. Roots are nullable existing S01 NativePathReport descriptors, absolute, lossless and validated; presence exactly follows S01 selection requirements. `selection` is the exact strict S01 WorkbenchSelection. `active_generation` is nullable u64, indexing `prepared` by sequence. It is an index into this configuration's immutable publication history, not an upstream generation or journal sequence.

Each prepared row has EXACT `sequence,profile,root,binding_sha256`: contiguous zero-based sequence in append order, captured profile name, absolute native prepared root, lowercase64 binding SHA. A profile's active index must exist, name that profile and carry its expected binding; arbitrary missing indices/duplicate sequence cannot be tolerated. Prepared rows survive profile removal or reconfiguration, so name reuse does not pretend a historical row was built under the new policy. Each successful refresh appends one row; equal view binding digests at different NEW roots are permitted and remain separate sequences. No created-at timestamp, random token or exporter-generated nondeterminism is necessary in this authority.

The ordinary config reader validates file shape/local cross-references, not every prepared root or dictionary. Listing/history can remain usable when an inactive old root is absent. Active open performs only S01 minimal open/currentness plus expected binding equality. A status/explicit availability command may inspect its requested roots with a stated scope; it is not an automatic query setup audit.

The CLI accepts source/root paths as native argv PathBuf values, resolves direct relative paths against ONE captured cwd, then persists absolute NativePathReport. It does not force non-UTF8 paths through JSON PathBuf strings. No relative-path alternate wire or lossy display fallback. Explicit config parent must exist. Reject a final symlink configuration destination before writes, preserving it; regular-file replacement follows the publication policy below. Ancestor symlink security/authentication is not newly claimed.

## 3. Public API spine (prospective until accepted S01 reconciliation)

Placement: store `workbench_profiles.rs` owns strict file policy/publication/captured identity; existing search `workbench.rs` owns configured reusable queries. Existing CollectionProfiles stays byte/code-compatible. APIs are proposed, uncompiled; final exact DTO/error fields and readset must be frozen before issue.

- `WorkbenchProfiles::read(config: impl AsRef<Path>) -> Result<Self, WorkbenchProfileError>` reads precisely that file once; retains bytes, exact SHA, parsed private validated wire.
- `profile(name: Option<&str>)` selects named/default, with distinct MissingFile/NoDefault/UnknownProfile/Unprepared errors. `report()` and `history(profile: Option<&str>)` return declared metadata without opening inactive roots. `verify_unchanged()` compares exact current file bytes to capture; no normalization or silent reread/reselect.
- `configure(config, request, expected_revision: Option<u64>)` sets roots+complete selection. None is valid ONLY when the config does not exist; an existing file requires exact Some(current revision). A semantic no-op preserves original bytes/revision/active index; a real source/selection change clears active index and retains ALL prepared history. Optional make_default is explicit. It does not perform a model build.
- `set_default(config, Option<&str>, expected_revision:u64)` chooses an existing profile or explicitly clears; `remove(config,name,expected_revision)` removes exactly that profile, clears matching default, retains prepared history, and never deletes any root. Missing profile is a typed error, not idempotent silent success. No-op default change preserves bytes/revision.
- `refresh(config,name:Option<&str>,destination,expected_revision:u64)` captures the LATEST profile under the writer lock, builds exactly one NEW root via accepted S01 `build_new`, then atomically publishes its active index/history row. No arbitrary override selection within refresh, no in-place root replacement and no hidden automatic retry.
- `ConfiguredWorkbenchView::open(config,name)` captures exact config/profile/active prepared row, opens that exact S01 root, compares full binding SHA to configured expected SHA and actual profile source roots/selection, then verifies unchanged file/current dependencies before returning. It retains captured bytes/identity, not a live mutable selector. Do not bypass policy by accepting a correct binding digest belonging to a different profile selection.

Every public Result has #Errors and matchable non_exhaustive typed errors, source chains/boxed existing WorkbenchError retained. Freeze named categories before issue: IO/current-directory/strict-decode/native/version/policy, MissingFile/NoDefault/UnknownProfile/Unprepared, revision Conflict, Busy, ConfigChanged, binding mismatch, source stale, and publication Indeterminate. No stringify-and-empty fallback. ConfigChanged may wrap actual path/missing reason without inventing observed bytes. S01 build errors remain distinguishable.

## 4. Writer lock, CAS and exact publication boundary

Follow the source-grounded existing profile writer semantics without claiming that its private ConfigWire/publish helper can be called from another module. A small private implementation here may share the established approach; no broad generic configuration framework/refactor or old-profile behavior change. A caller-visible expected_revision is checked after acquiring the sibling exclusive writer lock and reading the latest bytes; it is never checked against cached pre-lock state. Lock create_new owns its actual file identity; Busy leaves it alone, no timeout/stale-lock deletion or automatic retry. Guard drop removes only the lock/stage inode this operation created, never a replacement sentinel.

For refresh:
1. Resolve explicit paths once; acquire config writer lock; read strict latest config; check expected revision and resolve named/default profile. Drop any source readers before build stages as in S01. Do not hold SQLite readers across a writer hook.
2. Invoke S01 build_new exactly once into the explicit NEW destination with that captured request. It verifies models at this explicit boundary; existing roots/source authorities unchanged. A build failure may leave a partial new root, never publishes active index, and does not trigger a retry/cleanup.
3. Check new view currentness using fresh short readers, compare captured config bytes against path while locked, construct one appended prepared row and next active index/revision. No semantic query/model reconstruction here. Keep old active/history snapshot until publication.
4. Serialize proposed config; create_new exclusive sibling stage, preserve existing mode (first file0600), write+sync; recheck exact old bytes/absence immediately before rename; rename stage over regular config and sync parent. Preserve the narrow noncooperating-editor check-to-rename race as a limit, not a claimed filesystem CAS/transaction. No cross-file atomicity with dictionary/journal/catalogue.
5. Recheck visible config against proposed bytes and source currentness after publication BEFORE success; lock may then drop. A subsequent observed config/source mutation suppresses success and is reported with actual publication context. DO NOT claim prior active index was rolled back if rename already happened. Directory-sync failure is Indeterminate with prior/proposed revision+hash and best-effort actual observed identity. No automatically repeated build or file write.

A new root may be complete even when config publication fails. A published config may point to a now-stale root after a later source write. Those are explicit inspect/retry choices, not corruption disguised as success or promises of joint atomicity. Stdout acknowledgment may fail after either durable publication, following the shared emitter's existing commit-before-output policy. No new protocol or rollback claim.

The cooperating-writer lock spans the refresh, including its expensive build; this deliberately favors a simple truthful publication boundary over concurrent profile writers. Readers remain read-only and see the old or new whole config; no lock waits/retry loops. Finite race controls must prove a writer actually committed at the intended mutation window, not a counter/hook while a held DELETE-reader merely caused Busy.

## 5. Configured query identity and availability boundary

A configured wrapper retains lazy Full/Compact S01 engines just as direct mode does. No per-query full Dictionary clone, seal/body verification, history reconstruction, all-descriptor fingerprint or automatic refresh. Capture identity: config native path/version/revision/exact SHA + resolved profile name + active prepared sequence + original view binding SHA. `effective_binding_sha256` is a separately versioned ordered typed hash of those fields. It is NOT the base/curation digest or Compact snapshot digest.

Every operation first verifies exact config bytes/current S01 dependencies, executes, then performs fresh postchecks even on an inner error; post-change suppresses output with typed stale/config-change precedence. Never reuse a pinned SQLite reader between checks. Named/default mode is recorded explicitly in the capture, so switching default cannot silently retarget an existing engine. Conservative policy: ANY config byte change invalidates captured configured engines, even an unrelated profile/comment/format change; semantic no-op writer preserves bytes. A new engine may select new default, but old cursors/references remain bound to prior identity.

The actual cursor/detail mechanism must be frozen against accepted S01: use the EXISTING snapshot manifest generation field with effective binding for configured Full/Compact engine construction, keeping derived-state digest/member/selected release IDs unchanged. Existing engine public open_snapshot supports caller generation. Do not create a new outer cursor codec, rewrite token payload strings, or change persisted direct view binding. Pass captured effective identity into existing workbench engine initialization inside its module; do not expose a general unsafe caller-supplied trusted-binding public shortcut. Public configured response has its small config/profile identity plus original view binding and S01 small selection; complete pins/resolutions remain info-only, matched Full/detail bodies complete. Exact response/error fieldsets and Readable labels still need final accepted-S01 reconciliation before issue.

Removal/reload is an EXPLICIT external source lifecycle event, using current CollectionCatalogue APIs on task-owned roots: it makes old current views stale; refresh can publish the new available selection only after a valid selection reconfiguration if a formerly required selected pack is absent. Disable removes a pack from selected payload admission, never edits the upstream corpus or rewrites pinned contexts; any binding using that disabled pack must be removed explicitly (then existing Unavailable/Unresolved), not silently dropped. Historical owned selection retains its selected revision after later appends; Head refresh observes new head. Old prepared roots remain inspectable as historical artifacts but live direct/configured query uses its declared freshness rule, never fallback to an older generation.

S02 owns truthful EXPLICIT availability/status reporting for configured inputs, including registered-only/removed/disabled/unselected pack distinctions and missing active preparation. It must not call catalogue.list/inspect (which perform advisory filesystem probes) on every ordinary open/query. A narrow metadata-only roster in existing store/collections.rs can use registration keys/summary_json/current generation and maintenance::installation_state; source release summaries omit assertion arrays. Exact status DTOs/error precedence/readset remain S02 pre-issue work after accepted S01. Status reports retained metadata state; original/installed path disappearance stays advisory under the declared minimal scope unless explicit verification is requested.
