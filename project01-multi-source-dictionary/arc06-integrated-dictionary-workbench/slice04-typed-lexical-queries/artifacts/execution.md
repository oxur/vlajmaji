## Contract understanding grounded in the issued text

S04 adds a dedicated version-1 `vlajmaji-workbench-lexical` family for exactly two operations: ASCII-case-insensitive literal definition-substring matching and exact-spelling matching of records that are actually stored as Forms. Existing DictionaryRequest/Exact/Resolve/reference, S01–S03 wires, and old renderers remain unchanged; S05 owns Links. The new request has strict typed JSON (including required nullable keys), and the Full/Compact direct/configured outputs have the exact field sets in prompt §2. No `Value`-first decoding or duplicate-key collapse is allowed. Errors preserve the typed `Dictionary(InvalidJson)` chain for serialization failures; `DictionaryQueryError` itself has no `InvalidJson` variant.

Reverse matches retain real Lexical assertion occurrences; Form matches retain real FormRecords, including zero-association forms, and do not fabricate assertions or run computations. The two legacy roles map only to `SourceReportedForm` and `AssignedRafsi`; the other five FormKinds have no mapped role. Form association counts are a union of eligible assertion IDs, not a sum across forms. The issued rank/order and pre-page totals govern paging; Full and Compact share selected identities/order while retaining their distinct row shapes. Compact indexes have no entry-to-assertion or computation map, so implementation must use the existing retained typed document and ordinals without adding an index or whole-model clone. Detail is a new strict form-detail key, distinct from an assertion key, and uses the cached Compact engine.

The six new methods preserve the existing freshness protocol: PRE, all validation/setup/query work inside the captured inner result, release readers before the mutation hook, then a fresh POST whose error wins over either success or inner error. Configured identities use the effective binding. CLI parsing, native file errors, JSON/readable output, BrokenPipe, and Other write failures keep their typed existing boundaries; no ambient default store or stdin/JSON-argv route is introduced. Existing examples/docs cover the 0.3 workbench only; their 0.2 dependency snippets do not expose these APIs. ## Readback clarification — explicit identity and evidence relationships

The fieldset citation in the “Contract understanding” paragraph refers to **plan §2** (the exact new wire fieldsets), not prompt §2. This is a citation correction only; the issued packet remains unchanged.

A stored Form is selected from its actual Form+Entry and selectable source. It does not require an eligible assertion, current owned-head membership, or release membership. Its original SourceEvidence remains in the result when its referenced capture is unavailable, with the declared `CatalogueOnly` / `missing_capture` status. Loss of a required related row for an otherwise loaded/valid path is `Integrity`; it must not be converted to an unavailable-capture status.

Cursor identity binds the typed query, caller-ordered source selectors, resolved sources, alias scope, format, and direct/effective binding. Page size is intentionally excluded, so an issued cursor can continue with a different positive page size. Form-detail identity instead binds form/entry/computation content digests and the direct/effective binding; it remains valid across filters within the same view because it does not encode a query.

These are separate digest domains: direct binding or configured effective binding identifies the view; state/model SHA identifies recorded source state; Compact snapshot SHA identifies the compact projection snapshot; cursor query/checksum hashes identify the typed cursor request/body; and detail-key digests identify typed form, entry, and optional computation rows. None substitutes for another. Readable output is compared by complete semantic value where appropriate; independent cursor and hash oracles compare exact typed serialization bytes and declared field order.
