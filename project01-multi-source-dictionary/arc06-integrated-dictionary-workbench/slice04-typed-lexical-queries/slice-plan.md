## Concrete semantic direction

### ReverseDefinition

Require a nonempty literal UTF8 `contains`. Match ONLY `Presence::Value(TextValue).text` after `to_ascii_lowercase` on both input and stored text. Do not trim, case-fold Unicode, parse HTML/markup, search notes/glosses instead of definitions, tokenize, interpret wildcard syntax, or compare FTS ranks. Missing/Null definitions do not match. Spaces, punctuation, quotes, NUL and non-ASCII remain literal; the positive/negative oracle must discriminate these. Select only Lexical assertion occurrences permitted by the same admitted source/release/owned-head overlay and requested source/alias filters as S01/S02.

### Form

Exact bytes on stored FormRecord.spelling. Proposed request carries `value`, required-null `role:Option<FormRole>`, required-null `kind:Option<FormKind>` and existing source/page options. The legacy role mappings are EXACT SourceReportedForm→FormKind::SourceReportedForm and AssignedRafsi→AssignedRafsi; no mapping for the other five kinds. Both optional filters are conjunctive. With neither filter all SEVEN actually stored kinds may match; this is an explicit new typed stored-form policy, not a claim the old legacy corpus contained those kinds. Never generate or infer a missing form. Full output must show complete matched forms/evidence/computation; Compact must retain exact kind and matched form IDs plus its same-cache complete detail. Matching a ComputedStem/ComputedComponents/GeneratedCandidate is labelled computed stored material, not an attested source form or new computation. FormRecord is a FIRST-CLASS match with its real form ID and complete owning EntryRecord, source, evidence and optional computation identity, not a fabricated DictionaryHit/assertion/occurrence. A valid stored form may have ZERO eligible associated assertions, especially computed forms; retain it as a form record with an explicitly empty associated assertion roster rather than inventing a source occurrence. The new typed policy searches stored forms present in the prepared model for the resolved selectable sources; it does not claim those forms are all selected lexical assertions. A zero-associated result is explicitly labelled RETAINED STORED RECORD (no currently eligible assertion), never a current-head/attested occurrence merely because its source is selectable. The associated assertion roster independently uses the actual selected release/head/Lexical policy and keeps all competing occurrences. Multiple matching forms remain distinct form IDs even when their associated assertion populations overlap. S05 still owns running analyses/generation and caller proposals.

### Links: two honest evidence types

1. **Explicit typed relation:** preserve the actual RelationRecord verbatim, including origin role, kind, scope, direction, target, source evidence/editorial revision. No fabricated relation is stored or described as source-attested. No spelling-derived target where a typed target already exists.
2. **Parsed source clause:** factor/reuse the SAME see-also-braces-v2 pure parser from lexicon/lib.rs; expose a small parsed-clause result over borrowed decoded note text rather than constructing an Archive or trusting a caller-supplied body identity. The legacy wrapper continues to use the same parser and preserve byte-identical parsing behavior. New result retains ContextRecord ID, its actual assertion/occurrence/evidence, original target spelling, UTF8 byte offsets INCLUDING braces and original rule ID. Do not strip HTML, alter math exclusion, marker boundaries, clause delimiters or duplicate tokens. Only actual retained Note Value text is parsed; Null/Missing and non-Note contexts are not substitute evidence. This derived parser result NEVER becomes a stored/authored RelationRecord.

New graph seed population is all selected eligible occurrences with exact start spelling, within resolved requested sources. Parsed-clause target resolution preserves the original exact-spelling policy across admitted selectable sources (all competing matching occurrences), followed by the same requested source/head/release/eligibility filter for emitted/traversed candidates. No unknown source can become admitted through a spelling match. Preserve unresolved clause edges even when no selected target exists; no guessed winner. The exact source-filter behavior, edge ordering and cycle/duplicate policy are frozen below before issue rather than delegated to CC.

For typed targets reuse the admitted lower format-local reference provider/S03 boundaries, never reopen a default or promote catalogue-only metadata to payload. Follow only actual confirmed, eligible, selected target occurrences; retained unverified/unresolved/catalogue-only evidence remains visible without becoming a traversal hop. Local Entry expands its actual selected eligible assertions; Local Assertion is role-exact; Form/Sense expand only their actual explicit entry/member identities. Preserve the target response/native certainty separately from the graph's selected occurrence set. No global format-status rewrite: Full/Compact's existing aggregate priority can differ while confirmed occurrence traversal is explicit.

The new named traversal policy `typed-explicit-relations-v1` uses the following operational table. Actual model docs name these four values without specifying a stronger query algorithm; this is a declared traversal rule, not linguistic reciprocity or rewritten source metadata.

| Stored Direction | Allowed operational hop |
| --- | --- |
| Forward | actual origin → actual target |
| Reverse | actual target → actual origin |
| Bidirectional | both orientations |
| Unspecified | structural origin → target, retaining Unspecified verbatim |

Legacy parsed clauses remain forward origin→all exact targets under their original parser rule. RelationScope remains original provenance, not a license to change the typed origin role. Resolved requested sources restrict BOTH edge-owning authority and seed/emitted/traversed occurrence populations: an edge whose actual origin/evidence owner is outside that set cannot leak in through a reverse or cross-source target. Resolve typed roles/target candidates against the retained admitted model first, then apply selected Lexical/head/release and requested-source filters to actual hop occurrences. An unresolved/unknown/catalogue-only/unverified target stays explicit edge evidence and creates no invented traversal node. The final response will distinguish observed evidence from an actually followed permitted hop; exact incident-edge inclusion, minimum-depth/dedup and ordering remain final-readiness work, not an implicit choice left to CC.
