## Source-cited contract readback

The journal stores a complete validated `Dictionary`, not an editor patch or a search-derived view. `Dictionary::from_json_bytes` performs UTF-8 decoding, duplicate-key rejection, typed deserialization, then full graph validation (`crates/search/src/dictionary.rs`, constructor/parser and `validate` ranges). The late validator also checks owned revisions/heads, active assertions, tombstone identities, and the surrounding relationship constraints. The registry validator separately enforces version 1, unique source/contributor/distributor identities, alias rules, snapshot/occurrence bindings, and dangling-reference rejection (`crates/lexicon/src/registry.rs::validate_identity_prefix` and `validate_document`). The required S01 policy further narrows a valid genesis to one explicitly owned source/head/revision and caller-supplied provenance/notices; it does not let validation invent editorial or licensing facts.

The transaction cases are distinct. For the no-reader CAS case, writers A and B are both opened at persisted head r0 before A commits r1; B then attempts its r0 candidate and must receive `Conflict { expected: r0, actual: r1 }`, with no partial state. There is no pinned reader in that case. Separately, a read-only reader pins a DELETE-journal snapshot and can make a writer commit return Busy; after rollback, the caller drops that reader and deliberately retries. `DictionaryStore::open` confirms the existing local pattern of read-only `BEGIN DEFERRED` snapshots (`crates/store/src/dictionary.rs::open`); collection schema helpers show the current `BEGIN IMMEDIATE`, zero-timeout writer and read-only transaction conventions (`crates/store/src/collections_schema.rs`). The new plan requires a borrowed-`Connection` transaction guard, explicit `execute_batch` commit/rollback and `is_autocommit` observation because pinned rusqlite consumes `Transaction::commit`; a failed COMMIT with unestablished rollback is outcome-unknown, not an ordinary retry.

Summary reads have a deliberately smaller integrity boundary than `show`. `open` checks the family/version/minimum header; `head` and `history` check current/chain summaries and typed revision metadata but do not reconstruct every historical model or verify every historical body hash. Explicit `show` reconstructs the selected state from all 24 ordered typed vector prefixes, validates it, and verifies the canonical typed JSON SHA. Each edit appends exactly one revision, compares all old typed vector bodies/order as exact prefixes, retains all prior release flags and records, publishes a complete active set, and records removed prior active IDs as ordered tombstones. One writer decision is serialized by `BEGIN IMMEDIATE` and checks the persisted current head inside the transaction; the conditional head update is still required. SQLite integer revision bounds are checked before writes.

CLI input remains strict typed bytes from `--input FILE` or stdin, parsed before journal I/O. ROOT is explicit for every owned operation; no default/config fallback or import. The five nested operations are `owned init`, `edit`, `head`, `history`, and `show`; successful output uses the existing JSON emitter and typed report, errors use the existing structured envelope with `owned_<category>`. Output write/flush failure occurs after commit and cannot be reported as rollback; the requested revision/head must be inspected before retry. Existing `QueryOutput` has one JSON transport variant and the main CLI emitter owns write/flush/BrokenPipe behavior; there must not be a duplicate output lifecycle.
