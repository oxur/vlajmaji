### Admission and error precedence

CLI parses a request before config IO. Invalid JSON/runtime options use the new structured request error; Clap parser diagnostics stay Clap. Then explicit config decoding/version/profile validation precedes selected ROOT IO. A missing/malformed/unsupported catalogue is a typed catalogue error even for Unknown/Unresolved, because no coherent operational catalogue snapshot can be captured. Unknown/unregistered selected IDs reject; registered-only IDs are valid policy state. Constructor and `selection()` MUST succeed for a valid catalogue with no generation, all-disabled membership or missing/unsupported derived state and report those states; they never require the full engine or All verification.

For Exact: (1) validate managed outer cursor encoding/version/checksum, then compare its snapshot binding; stale wins before no-enabled/unavailable errors. (2) require at least one enabled effective member and every enabled requested pack to be installed and producer-selectable; disabled default members alone are deliberately omitted with availability. (3) require the current Unified payload's minimum/recorded-state/read/decode boundary; no fallback. (4) reuse existing source/alias and inner-cursor/spelling/order checks. An unrelated enabled requested registered-only pack is fatal for aggregate exact, even if source filters would otherwise hide it. Default membership vs explicit override is reported separately. Fresh no-cursor requests to all-disabled or missing-derived state get the corresponding unavailable error, not stale. Config/cataloque failure before a valid snapshot remains its typed error; it cannot be labeled stale merely from an unreadable cookie.

For Resolve: structurally validate the requested role/scope against retained metadata first. Unknown and nonempty Unresolved return their existing status without opening payload, regardless of all-disabled/no-generation/unrelated unavailable packs. A known registered-only, policy-disabled or policy-unselected target returns metadata-only with explicit reason, not a physically-missing claim. An enabled selected installed target resolves using its available payload even when a DIFFERENT requested pack is unavailable; no whole-set exact admission is imposed. Producer exact-eligibility is not a ban on explicit raw references: source-unselected or individual excluded raw targets remain resolvable with current_eligible:false. However, selected installed target with missing/corrupt/unsupported derived DB fails typed at that boundary, rather than being disguised as CatalogueOnly. NoMatch/Unverified describe attribution matching independently of operational reason.
