## Binding contracts

**Identity and state.** A source is an asserting dictionary; a distributor, collection, normalized release, capture and physical database are different identities. Lensisku's jbotci/La receipts remain one source authority with separate occurrences. Registration records known catalogue metadata; installation means verified local payload/backend artifacts exist; enablement controls query participation; default/profile membership chooses a selection. None implies another. Enable/default membership is local collection/user policy; never implement it by rewriting immutable source ReleaseRecord.selected fields or history. Resolve the catalogue/profile overlay and derived selection policy before S03. Source filters resolve source IDs/aliases, not pack or distributor names. Collection selection must be explicitly distinguishable from source filtering.

**Installation and lifecycle.** All inputs are named local files or already materialized sealed Full packs; no implicit network/download, build-script acquisition or public redistribution. Public Held status does not prohibit authorized internal local installation. Verify raw pins/seal/model and derived-store completeness before activation; retain content notices/holds. Create fresh destinations exclusively, never overwrite an occupied unknown target. “Install all” requires all four named upstream inputs/packs; missing or Held inputs are never silently skipped. Before S02, choose the explicit local batch manifest/provider contract and failure/retained-staging policy: a partial failure cannot report all installed or activate an incomplete requested generation, and the prior active selection remains intact. Identical complete installs are idempotent; same IDs with unequal metadata/payload fail explicitly. Partial staging/failure is never an active installed generation. Update retains prior release/history and explicit provenance; disable keeps installed bytes; remove retains catalogue identities/history and distinguishes absent payload; exact reinstall restores reference availability without retargeting. Distinguish registering existing user-managed paths from a tool-owned install. Removal of user-managed data only unregisters/disables the reference unless deletion is separately authorized; tool-owned deletion requires recorded ownership and a scoped policy, never broad parent/symlink cleanup. Scope any eventual payload purge explicitly, not as incidental cleanup.

**Queries and snapshots.** Unfiltered defaults select configured enabled/available collections; explicit source filters are applied within that selection. A request pins one coherent catalogue/profile/artifact generation, including release selection, availability, query/projection policy and ordering. Membership/update/disable/remove/default changes invalidate incompatible cursors with typed errors. Readers cannot see mixed generations or silently lose a collection. Define locking/publication/recovery before dependent code; do not claim cross-file WAL atomicity. If versioned immutable artifacts plus an activation pointer are chosen, specify durable switch, reader pinning and interruption recovery; that is a proposed mechanism to assess after S01, not a topology decision now.

**Availability and references.** Distinguish unknown/unregistered, registered-uninstalled, installed-disabled, enabled-but-missing, corrupt, unsupported-version/conflicting release, removed and reinstalled states. Successful zero-hit means searched available selected data. Explicit unknown/disabled/unavailable selection and corrupt input must not become an empty success or fallback to a different store. Retained local/catalogue references preserve role, capture/release/native IDs; removed data resolves catalogue-only/unavailable, exact reinstallation recovers the original identity, and updates do not silently retarget. Existing explicit STORE errors/full response semantics remain compatible.

**Output and payload.** Existing full JSON remains available with unchanged semantics/default behavior on existing routes unless a separately versioned compatibility decision explicitly changes it. New readable/compact routes must declare representation at the library/query boundary **before** full response metadata, raw rows and unrelated release inventories are hydrated/cloned/serialized. Rendering full JSON through jq or discarding fields after full construction is insufficient. Compact availability contains selection/state summaries and stable detail references, **no unrelated whole-release assertion-ID inventories**. Keep every matching occurrence, source/release/capture/native provenance, source-group/page totals, ordering and cursor meaning. Explicit missing/null/unknown states stay distinguishable in selected fields; omitted heavy detail is declared and reachable by a detail/reference operation. Readable output must not select a winner or flatten alternative definitions. Detail/format/schema names are decisions held before prompts.

**Defaults and migration.** Preserve existing explicit STORE and legacy build/search/info compatibility. Reuse the established DATA_HOME resolution and logical `vlajmaji/stores/default` convention; decide how profiles/catalogue and selected backend artifacts map to that logical default without preselecting file topology. New configuration capability must follow source AGENTS' confyg requirement (twyg only if logging is introduced); exact file paths/schema/override precedence are readiness decisions. New parent directories private0700 where supported; existing modes unchanged, native OsString/PathBuf retained without panic/lossy routing. Query/list/info/resolve do not create or install absent data. Old standalone/default store migration is explicit and reversible, not automatic overwrite or hidden activation. Implementation/review uses isolated temporary XDG/HOME/scratch; the user's installed default is not silently switched even when future A04 execution is authorized.
