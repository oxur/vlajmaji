## Settled direction, requiring accepted S02 API reconciliation

- A separate public `DictionaryStore` in store crate is additive and stores the S02 `Dictionary`. The foundation fixture uses one caller-owned directory/database; it does not select A04 one-file/ATTACH/fanout topology. No production editing, corpus import or query API in S03.
- `create(fresh_path, &Dictionary)` validates before path creation, refuses existing paths, builds in one transaction with an incomplete marker until committed, retains exact canonical dictionary JSON bytes and original legacy archive bytes, and never mutates inputs. `open(path)` uses no create flag, is read-only, and rejects wrong format/schema/incomplete/hash/foreign-key/schema/projection mismatch. `dictionary()` gives borrowed immutable loaded validated state; bytes, flush/size and path/error details are finalized against actual source.
- New schema has an explicit dictionary format discriminator and schema version independent of legacy SqliteStore schema1. Wrong-family opens must reject without writing or silently migrating. Rebuild is explicit into a new path, retaining the old database/archive.
- Canonical complete document bytes are a rebuild source, **not a substitute for relational projection**. Concrete role tables, keys, foreign keys, scalar columns, source/native IDs, ordered child tables and presence discriminants persist every twelve-area field. JSON is allowed for genuinely raw native/extension/annotation values and canonical backup; it cannot hide the typed model in one payload column.
- Exact source/capture/occurrence identities retain the existing length-prefixed record_id encoding. Capture identities and occurrence identities have unique tuple columns as well as stable IDs. Expected missing capture identities are catalogue rows; payload/loaded-row tables are separate subsets, so absence remains explicit and FK-valid. Do not invent raw rows/zero counts for missing packs.
- Global metadata entity IDs use a base role registry plus role-specific typed tables. Typed references must enforce intended role (direct FK to role table, or role+ID composite FK with allowed-role check), rather than merely foreign-keying to an arbitrary existing entity. Deferrable FKs permit valid forward/cyclic references without disabling checks. All table schemas use explicit PK/unique constraints; connection enables foreign_keys.
- Presence Missing/Null/Value is stored with explicit state plus value columns; a supplied empty string stays a supplied value. TextValue language/markup and native/mapped POS remain separate scalar fields. Native raw ordered fields keep name, encoding, raw lexeme and ordinal; repeated field names survive. Text/raw bytes use BINARY equality and no normalization. Vector ordinal preserves declared order independently of supplied slot/component order.
- Large u64/usize model values cannot be silently cast to SQLite signed integers. Declare a lossless representation (canonical decimal text where full unsigned range is possible); vector ordinals may use checked integers. No serde_json::Value floating-point coercion for RawJson/native lexemes.
- Strict reopen validates format/completeness, exact canonical byte hash, Dictionary parsing/validation, expected schema shape, foreign_key_check, then **all relational rows and scalar values** against a deterministic projection of the validated document. Mere stored row totals, self-reported projection hashes or a handful of sampled fields do not detect valid-but-wrong values. A transaction/snapshot bounds open-time checks; document what state the immutable loaded Dictionary represents. No adversarial-security guarantee is implied.

## Concrete table coverage to finalize after S02

The final packet must name exact columns/DDL; this inventory prevents silent fields being left in a sidecar:

1. Registry: sources with abbreviation kind/evidence/origin/order; contributors; distributors; ordered aliases/status/evidence; ordered lineage known/unresolved/evidence; capture bindings; occurrence attribution contributor/native entry/native assertion ID. Registry version retained.
2. Raw/catalogue: capture_refs (all loaded+expected catalogue bindings), raw_captures (loaded subset, exact bytes/hash and metadata presence/precision/locator), occurrence_refs (known stable identities), raw_occurrences (loaded subset and raw line), ordered native_fields with encoding/lexeme. Collections/source/description, components/languages, releases with revision/version/normalizer/availability/selected/unknown accounting and unit; ordered release captures/assertions/diagnostics.
3. Entry: all spelling/language/script/native class/selmaho presence columns, explicit mapped POS state/value/rule. Assertions have typed entry/occurrence refs, native sense/language/definition/score presence, eligibility/reason; ordered native timestamps with exact RawJson and precision. Existing registry retains author/native entry/native assertion authority.
4. Context: typed context kind/value/translation ref and exact source evidence. Distinct definition/gloss/note/etc remain distinct.
5. Arguments: frame/assertion/evidence; slots with vector ordinal, supplied unique order, native label, description and grammatical role.
6. Morphology: form/entry/spelling/lang/script/pronunciation/kind/standing/source evidence/computation; ordered components with spelling/typed optional target. Assigned rafsi, reported form and computed/generated categories stay distinct.
7. Etymology: explicit etymology/assertion/statement/native kind/source evidence plus ordered components; null/empty/nonempty values survive. No inference.
8. Relations: origin typed role/ID, kind including Other label, direction/scope, target discriminant; separate local role/ID vs catalogue source/release/native IDs/occurrence vs unknown/unresolved; evidence/editorial revision separate.
9. Owned: revision/source/parent/editor/time/precision/rationale, ordered full assertion set and tombstones; source head. Immutable prior rows retained.
10. Editorial: sense/editor/revision/rationale plus ordered assertion memberships, distinct from native sense and default query selection.
11. Computed: computation tool/version/policy/profile/explanation; ordered inputs with occurrence/entity/literal discriminants and typed refs; annotation run/target/kind/raw value/explanation. Ordered extensions have existing owner/name/raw value/optional source evidence.
12. Terms: ordered code notices separate from per-release content notices, each text/locator/license presence intact; redistribution status and ordered supplied evidence. No inferred permission or publication.

Repeated SourceEvidence fields should use explicit occurrence FK/field index/citation presence/start/end columns. Raw bounds need loaded fields; unavailable evidence has the S02 validation limit. LocalRef target role+ID must not collapse to a JSON string. Ordered components for forms and etymologies can use separate parent-FK tables. Release/timestamp/notice children need ordinals and concrete parent FKs. TextValue can use explicit prefixed scalar columns; a generic EAV table alone is not the broad concrete schema contract.

- Start from the complete accepted S02 fixture, expected9 loaded captures/20 raw+normalized occurrences/14 entries/7 raw farvi and10 capture bindings including Missing. Adapt legacy19-row/8-capture archive subset and preserve exact legacy bytes. No fixture population silently changes in S03.
- Fresh create, drop, read-only reopen, entire Dictionary/document equality, every capture byte vector and legacy archive equality; public external caller with unique package/binary name. Example consumes the S02 JSON output and explicit fresh store path, then reopens and self-checks. It must not need a private test accessor.
- Integration tests use existing rusqlite dependency directly to assert **meaningful column values** in every coverage family: repeated farvi native IDs/contributor, missing/null/empty native and normalized fields, exact MOI/POS split, source score/date lexemes, prose-only4/5 vs actual structured frame, blank LLG cpana rafsi vs reported cpan vs computed snim, form standing/component order, etymology null/empty/nonempty, all relation targets, missing counts NULL vs available zero, owned r1/r2/head/tombstone, editorial/computation provenance, nested raw values and separate terms. Table counts are supporting accounting only.
- FK/role negative controls perform actual invalid inserts/updates with foreign_keys enabled (wrong source/entity/parent/ref), duplicate stable ID and membership/order checks; prove both SQL and model invariants at their intended layer. Semantic source agreement can remain validated by model/projection check where SQL cannot express it; document that boundary.
- Clone fresh store fixtures before each tamper control; do not reuse partially modified files. Test version/format/incomplete marker, canonical hash/bytes, raw payload/projection mismatch, missing table/column/index/FK/schema shape, deleted/added valid rows and **valid-shaped scalar edits** such as a definition, native ID, availability, etymology statement, owned head or source evidence. Restoring complete rows at same counts must still reject on reopen. Hashing canonical bytes alone does not detect projection edits.
- Explicit rebuild recipe: old SqliteStore open→archive_bytes→Dictionary::from_legacy_archive with supplied registry+metadata→DictionaryStore::create(new path). Old schema/database remains readable and unchanged. Cover accepted archive versions1/2 and legacy empty SourceMetadata; no auto migration or empty-field rejection. Additional opaque capture remains new-model-only.
- Existing default/no-default/all-feature/locked workspace/docs gates remain required; all builds serialized in task target. Run real outside caller and a separate CDC SQL inspection/control path. Preserve every failure/repair and row denominators. Detailed S03 ledger/API/DDL and assignment follow accepted S02 inspection.
