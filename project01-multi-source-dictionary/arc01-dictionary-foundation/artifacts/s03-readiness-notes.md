## Settled direction, requiring accepted S02 API reconciliation

- A separate public `DictionaryStore` in store crate is additive and stores the S02 `Dictionary`. The foundation fixture uses one caller-owned directory/database; it does not select A04 one-file/ATTACH/fanout topology. No production editing, corpus import or query API in S03.
- `create(fresh_path, &Dictionary)` validates before path creation, refuses existing paths, builds in one transaction with an incomplete marker until committed, retains exact canonical dictionary JSON bytes and original legacy archive bytes, and never mutates inputs. `open(path)` uses no create flag, is read-only, and rejects wrong format/schema/incomplete/hash/foreign-key/schema/projection mismatch. `dictionary()` gives borrowed immutable loaded validated state; bytes, flush/size and path/error details are finalized against actual source.
- New schema has an explicit dictionary format discriminator and schema version independent of legacy SqliteStore schema1. Wrong-family opens must reject without writing or silently migrating. Rebuild is explicit into a new path, retaining the old database/archive.
- Canonical complete document bytes are a rebuild source, **not a substitute for relational projection**. Concrete role tables, keys, foreign keys, scalar columns, source/native IDs, ordered child tables and presence discriminants persist every twelve-area field. JSON is allowed for genuinely raw native/extension/annotation values and canonical backup; it cannot hide the typed model in one payload column.
- Exact source/capture/occurrence identities retain the existing length-prefixed record_id encoding. Capture identities and occurrence identities have unique tuple columns as well as stable IDs. Expected missing capture identities are catalogue rows; payload/loaded-row tables are separate subsets, so absence remains explicit and FK-valid. Do not invent raw rows/zero counts for missing packs.
- Global metadata entity IDs use a base role registry plus role-specific typed tables. Typed references must enforce intended role (direct FK to role table, or role+ID composite FK with allowed-role check), rather than merely foreign-keying to an arbitrary existing entity. Deferrable FKs permit valid forward/cyclic references without disabling checks. All table schemas use explicit PK/unique constraints; connection enables foreign_keys.
- Presence Missing/Null/Value is stored with explicit state plus value columns; a supplied empty string stays a supplied value. TextValue language/markup and native/mapped POS remain separate scalar fields. Native raw ordered fields keep name, encoding, raw lexeme and ordinal; repeated field names survive. Text/raw bytes use BINARY equality and no normalization. Vector ordinal preserves declared order independently of supplied slot/component order.
- Large u64/usize model values cannot be silently cast to SQLite signed integers. Declare a lossless representation (canonical decimal text where full unsigned range is possible); vector ordinals may use checked integers. No serde_json::Value floating-point coercion for RawJson/native lexemes.
- Strict reopen validates format/completeness, exact canonical byte hash, Dictionary parsing/validation, expected schema shape, foreign_key_check, then **all relational rows and scalar values** against a deterministic projection of the validated document. Mere stored row totals, self-reported projection hashes or a handful of sampled fields do not detect valid-but-wrong values. A transaction/snapshot bounds open-time checks; document what state the immutable loaded Dictionary represents. No adversarial-security guarantee is implied.

### Expected identities and role representation

Capture-reference table includes union of loaded refs, registry bindings, release captures and known occurrences referenced by assertions/evidence/diagnostics/catalogue targets/computation inputs. Registry snapshot binding is its own optional relation, distinct from a loaded raw-capture row; missing expected captures need neither fake bytes nor fake raw occurrences. All known occurrence identities get a stable tuple-key row, while raw_occurrences is a loaded subset with exact locator/line. Tuple uniqueness and derived stable-ID correctness must be verified at reopen, retaining record_id's full length-prefixed byte encoding. Empty legacy namespace/locator metadata policy stays at the model boundary; do not introduce nonempty constraints over valid preserved metadata.

Use one globally unique entity-role table, plus typed role tables. For LocalRef's four roles, nullable direct target columns entry/assertion/form/editorial_sense with a discriminant/one-of CHECK and concrete FK are an uncomplicated alternative to a generic unconstrained entity_id. A role+ID composite FK with allowed-role CHECK is also sound if specified completely. Extensions can target any existing metadata entity; that wider owner role is deliberate. SQL FK targets reflect actual declared model roles; unavailable membership does not relax them. Deferred FKs enable valid forward refs/relations; enable enforcement on every writer and run foreign_key_check. Semantic cross-row source agreement can remain explicit model/reopen validation, but cannot be mistaken for a SQL FK guarantee.

### Concrete scalar/ordered representation detail

All top-level model/registry vectors have stored ordinals, even when IDs are their lookup PK. Canonical metadata/catalogue/registry version values are separate; dictionary JSON version1 does not equal legacy SQLite schema1. Parent child vectors have `(parent_id,ordinal)` keys; supplied slot/component order is an additional independent unique value, not a replacement for ordinal. SQL NULL for Option differs from Presence's three-state value. Prefix columns for each Presence hold state missing/null/value plus payload; CHECK payload NULL outside value, allow empty string at value. Presence<TextValue> requires outer state and text plus independent language/markup states/values; Presence<PosMapping> requires outer state and value/rule, no opaque typed-object JSON. Nonoptional TextValue keeps the same explicit language/markup columns.

Each SourceEvidence can be a concrete row with occurrence FK, nullable field-index canonical unsigned decimal, citation state/value and nullable offset start/end canonical unsigned decimals. Parent holds evidence FK; optional evidence stays SQL NULL. Source evidence identities can be deterministic projection-local keys tied to owner/ordinal, not invented lexical stable IDs. For typed optional ranges require both start/end or neither. Bounds and decoded UTF8 checks remain S02's validator duty, especially the explicit unavailable limitation.

Release accounting three Option<u64> columns are nullable canonical unsigned decimal TEXT, avoiding SQLite i64 truncation; catalogue_revision and any usize/u64 field use the same lossless strategy. JSON score/timestamp values retain exact RawJson string lexemes; text fields containing JSON-like strings remain text. Registry native entry/assertion IDs are optional exact TEXT, including Some(empty), and never copied into native sense. NamedTimestamp has field, exact value, precision and ordinal. Native fields retain encoding/name/raw_value and ordinal; repeated names remain separate. Source format_label is explicit string, not a rewritten SourceFormat inference.

Relation columns retain origin role, kind/Other label, direction/scope, target kind and distinct local or catalogue source/release/native entry/native assertion/occurrence values, unresolved text, source evidence and editorial revision. Computation input table discriminates occurrence/local typed entity/literal, with exact tool/version/policy/profile/explanation on its parent. Form/etymology component tables have concrete parents, ordinal/order/spelling and optional LocalRef target columns. Missing/null/empty etymology statements and source native kind remain typed. Code notices, content notices and redistribution evidence are distinct ordered child families. Every significant model field must appear in the final field→column map before issue, not be relegated to a serialized metadata object.

### Strict reopen mechanism and independent oracle separation

A practical complete integrity implementation can render the validated canonical document through the same deterministic projection into a fresh in-memory SQLite connection, then compare expected schema catalog and every actual table cell/row in PK/ordinal order, using SQLite typed Value (Null/Integer/Real/Text/Blob) without JSON-number coercion. Compare sqlite_schema user tables/indexes/views/triggers exactly against the canonical DDL shape; foreign_key_check and expected PRAGMA table/index/FK shape checks make the contract inspectable. No extra table/column/index/trigger or weakened FK may slip through, even if row counts agree. SQL implementation can choose direct expected rows instead of a second in-memory connection; full-value coverage is the binding behavior, not that helper design.

Reusing deterministic projection code for building/verification is not independent proof of correct field mapping. Therefore S03 tests and CDC's separate direct SQL inspection must each assert meaningful values from all twelve families against the accepted public fixture, plus complete dictionary/raw/archive equality. Representative valid-shaped scalar edits must reject even when row counts, schema shape and canonical hash are unchanged. Fresh clone per tamper prevents contamination. Add/delete/reorder rows, wrong FK/role, canonical/raw bytes, format/schema/incomplete and changed schema/index/FK controls are separate populations and must retain exact denominators.

Open under a read transaction/snapshot before integrity checks, retaining that transaction/connection for immutable store state if needed by S04. This aligns later indexed candidate SQL with the loaded Dictionary snapshot rather than an externally changed file. Do not use SQLite immutable-file flag as a substitute for actual snapshot/integrity behavior. Any borrowed immutable public dictionary represents that validated open snapshot; no production refresh/editor is implied. Later grouped lookup must actually select candidate assertion IDs through indexed SQL (BINARY entry spelling/source/eligible/selected-release joins), while an independent in-memory model scan remains its result oracle. No lookup is implemented in S03.

## Pinned SQLite API/snapshot and constraint-oracle readiness

During S02 refinement02 CDC read actual pinned rusqlite0.40.2 local primary source: registry path index.crates.io-1949cf8c6b5b557f/rusqlite-0.40.2/src/transaction.rs1–84/410–475 and lib.rs395–443/1184–1212, plus method inventory. Transaction borrows Connection; a store owning both cannot safely keep a self-referential Transaction field. A private Connection with manually begun DEFERRED read transaction before first metadata read is a viable snapshot design; no unsafe or public mutable connection is needed. Enable foreign_keys before starting the transaction. OpenFlags::SQLITE_OPEN_READ_ONLY refuses nonexistent files and creates no database, unlike default open's READ_WRITE|CREATE. Final implementation must verify actual flags and use a snapshot consistently for all integrity/candidate queries.

Prefer ordinary rollback-journal database construction for this immutable foundation fixture rather than importing legacy WAL assumptions: creation completes/closes its writer before readonly reopen; no WAL/shm artifact is required for the public open path. This is a local store implementation detail, not the later physical-topology decision. Document read-only snapshot lifetime. Tests that tamper or exercise SQL constraints must close held read snapshots first; otherwise a write-lock/busy error could falsely pass an is_err constraint test. Match actual SQLite constraint codes (FK/CHECK/UNIQUE as intended) rather than accepting any backend error. Each control starts from a fresh closed store copy; no shared partially mutated fixture.
