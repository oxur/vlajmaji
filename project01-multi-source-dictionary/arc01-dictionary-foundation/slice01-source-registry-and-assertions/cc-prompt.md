### IDs and public shape

Create exported `SourceId`, `ContributorId`, `DistributorId`: distinct private-string newtypes; `new(impl Into<String>) -> Result<Self, RegistryError>`, `as_str`, Display, Debug, Clone, Eq/Ord/Hash, Serialize as string, validated Deserialize/TryFrom<String>. Syntax is one or more lowercase ASCII letters/digits with the first byte letter/digit and remaining bytes from `[a-z0-9._:-]`. Reject uppercase, whitespace, slash, NUL, Unicode and empty; do not trim, lowercase or silently normalize. Different roles may share the same literal ID string without becoming interchangeable Rust types. IDs are project-stable and unrelated to namespace/hash/locator identity tuples.

Recommended two modules with reexports from lib. Public draft records are explicitly unvalidated plain input data (public fields are acceptable here); validated `SourceRegistry` has private fields and borrowed accessors. Supply these names and shapes (private helper names/local mechanics are discretionary):

- `SourceOrigin { Upstream, OwnedDraft }`; `AbbreviationKind { ProjectAssigned, Conventional }`; `AliasStatus { Active, Retired }`; `AliasScope { ActiveOnly, IncludeRetired }`. Public enums Debug/Clone/Eq/serde and non_exhaustive.
- `SourceRecord { id: SourceId, display_name: String, abbreviation: String, abbreviation_kind: AbbreviationKind, abbreviation_evidence: Option<String>, origin: SourceOrigin }`.
- `ContributorRecord { id: ContributorId, display_name: String }`; `DistributorRecord { id: DistributorId, display_name: String }`.
- `SourceAlias { source: SourceId, text: String, status: AliasStatus, evidence: Option<String> }`. Names are display only; selectors are source IDs, abbreviations and explicit aliases. Alias/abbreviation match is exact bytes/case. Nonempty, trim-equal, control-free strings required; internal spaces and Unicode display/alias text allowed. Conventional abbreviation requires nonempty evidence; ProjectAssigned must be labelled as such and may omit evidence.
- `LineageTarget { Known(SourceId), Unresolved(String) }`; `SourceLineage { source: SourceId, upstream: LineageTarget, evidence: Option<String> }`. Known requires registered target and nonempty evidence; unresolved requires nonempty locator/description and must not resolve/merge automatically. Directed edges are descriptive; no deduplication or inference. No cycle-based merging; self known edge is invalid.
- `SnapshotAttribution { snapshot: SnapshotIdentity, source: SourceId, distributor: Option<DistributorId> }`.
- `OccurrenceAttribution { occurrence: RecordIdentity, contributor: Option<ContributorId>, native_entry_id: Option<String>, native_assertion_id: Option<String> }`. Native values preserve supplied string bytes including empty (unknown is None), never derived from text; absent occurrence row means all optional identities unknown.
- `RegistryDocument { version: u32, sources: Vec<SourceRecord>, contributors: Vec<ContributorRecord>, distributors: Vec<DistributorRecord>, aliases: Vec<SourceAlias>, lineage: Vec<SourceLineage>, snapshots: Vec<SnapshotAttribution>, occurrences: Vec<OccurrenceAttribution> }` with `Default` version **1**, empty lists. Serde rejects unknown envelope/record fields rather than silently dropping future semantics. Source raw JSON unknowns are unaffected.

`SourceRegistry::new()/Default`; `from_document(RegistryDocument) -> Result<Self,RegistryError>`; `document(&self) -> RegistryDocument` (owned clone); `apply_document(&mut self, RegistryDocument) -> Result<(),RegistryError>`; `to_json_bytes`, `from_json_bytes`; implement validated serde Deserialize for SourceRegistry via document conversion so `serde_json::from_slice::<SourceRegistry>` cannot bypass invariants. Document validation before any mutation: supported version=1; all named fields; unique IDs per entity role; registered source/contributor/distributor foreign refs; one snapshot binding per exact SnapshotIdentity; one metadata binding per exact RecordIdentity; occurrence metadata must reference a bound snapshot. No validation may reinterpret legacy namespace/hash/locator values; capture existence is checked against Lexicon at view time (below). Source IDs and aliases cannot conflict with another source ID or current abbreviation. ### Attribution views

`SourceRegistry::validate_lexicon(&self, &Lexicon) -> Result<(),RegistryError>` checks every registered snapshot/occurrence binding against actual preserved captures, and every captured snapshot has a binding. A binding to a fabricated/stale ID is an explicit error, not invented provenance. Registry syntax/deserialization can validate its own foreign keys without owning a Lexicon; this two-stage distinction must be documented.

`SourceRegistry::attribute<'a>(&'a self, record: &'a CapturedRecord) -> Result<AttributedOccurrence<'a>, RegistryError>` returns a borrowed record/source/distributor/contributor/native-ID view. It validates snapshot binding, optional metadata and entity refs; record presence itself is guaranteed only by validate_lexicon or caller obtaining it from Lexicon, which docs must state. `SourceRegistry::attributed_records<'a>(&'a self, lexicon: &'a Lexicon) -> Result<Vec<AttributedOccurrence<'a>>,RegistryError>` first validates the whole relationship then walks `lexicon.records()` preserving insertion order and multiplicity. Each view exposes `record`, `source`, `distributor`, `contributor`, optional native IDs and source lineage (borrowed accessor or an iterator). SourceOrigin labels owned drafts distinctly. No source-backed form is promoted to assignment; no predictable stem becomes source attestation; Proposal remains separate and never appears in attributed captured records.
