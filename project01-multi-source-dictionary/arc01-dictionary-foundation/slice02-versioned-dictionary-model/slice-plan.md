## Binding design

Add `crates/lexicon/src/dictionary.rs`, reexporting the public model from lib.rs. Existing Lexicon, SourceMetadata, source parsers, archive v1/v2, IDs/forms/proposals, store and search remain unchanged. `Dictionary` is immutable validated state over an owned `DictionaryDocument`; plain draft records have public fields and `deny_unknown_fields`. No mutable editor or automatic linguistic analysis is implemented. All strings retain supplied bytes; only project-assigned EntityId/name/version/reference invariants are validated. Native empty/null/unknown values are not normalized away.

### Shared values and raw layer

- `EntityId`: private validated String newtype, separate from SourceId/ContributorId/DistributorId. Same ASCII grammar as the S01 IDs; new/as_str/TryFrom/Display/Eq/Ord/Hash/validated serde. Metadata IDs are globally unique across roles within one document; references additionally validate the required role. Native upstream IDs are **not** EntityId and remain optional supplied strings in registry attribution/raw fields. No identity is invented from text equality.
- `Presence<T> { Missing, Null, Value(T) }`, Default=Missing, default externally tagged serde; this preserves explicit normalized-field presence as well as canonical raw-field presence. `TextValue { text:String, language:Presence<String>, markup:Presence<String> }`; empty supplied text/language/markup remains present.
- `RawJson`: private string; `new(impl Into<String>)->Result`, as_str, validated Deserialize and string Serialize. Validate one syntactically valid JSON value with RawValue, retain its exact lexeme (including huge numbers and nested unknown shapes); do not parse/re-emit a Value. It is an opaque native/extension value, not a new policy changing the legacy parser's duplicate-key rejection.
- `CaptureRef { namespace:String, sha256:String }` and `OccurrenceRef { capture:CaptureRef, locator:String }`, plain strict serde records with Eq/Ord/Hash. `From<&SnapshotIdentity>`, `From<&RecordIdentity>` and explicit `to_snapshot_identity()/to_record_identity()` adapters copy exact fields; they never reuse display IDs or hash/normalize the legacy tuple. Existing identity structs stay unchanged.
- `NativeEncoding { Json, Text }`; `NativeField { name:String, encoding:NativeEncoding, raw_value:String }`. Json requires syntactically valid raw JSON; Text retains literal `null` as text. Ordered fields preserve unknown types and repeated names; no map deduplication. Canonical capture bytes remain authoritative. `RawOccurrence { locator:String, fields:Vec<NativeField>, raw_line:Option<String> }`. Locator unique within capture; raw_line carries an original text row when available. Missing field is absent from the vector, JSON null is a Json lexeme, and empty text/JSON string remain distinct; expose `RawOccurrence::fields_named(&str)->Vec<&NativeField>` rather than arbitrarily choosing one repeated field.
- `CaptureMetadata { source_name:String, format_label:String, locator:String, revision:Presence<String>, captured_at:Presence<String>, time_precision:TimePrecision, notice_locator:Presence<String> }`. Legacy supplied empty metadata stays empty; this is not the registry's validated display name. No date precision or URI is inferred. `RawCapture { identity:CaptureRef, metadata:CaptureMetadata, bytes:Vec<u8>, occurrences:Vec<RawOccurrence> }`; verify SHA256(bytes) exactly equals identity.sha256 and capture identities are unique. Captures may contain opaque/binary payload bytes; callers explicitly supply row accounting/fields and eligibility rather than silently interpreting them through Lexicon.
- `SourceEvidence { occurrence:OccurrenceRef, field_index:Option<usize>, citation:Presence<String>, offset:Option<TextRange> }`; `TextRange { start:usize,end:usize }` offsets in the **decoded UTF8 selected native field text**. Range requires a field_index and a Text field or JSON string field; bounds/UTF8 boundaries must be valid. Null/nonstring fields cannot carry a text range. An absent field_index cites the whole occurrence and has no range. This is supplied provenance, not semantic inference.

### Catalogue and terms

- `CollectionRecord { id:EntityId, source:SourceId, display_name:String, description:Presence<TextValue> }`.
- `ComponentRecord { id, collection:EntityId, native_name:String, languages:Vec<String> }`; LLG roots/cmavo/rafsi may be separate components. No names establish source identity.
- `Availability { Available, Disabled, Missing, Removed }`.
- `ReleaseAccounting { input_occurrences:Option<u64>, normalized_occurrences:Option<u64>, query_excluded_occurrences:Option<u64>, unit:String }` and `ReleaseDiagnostic { occurrence:Option<OccurrenceRef>, code:String, message:String }`.
- `RedistributionStatus { Unknown, Held, Permitted }`; `ContentNotice { text:Presence<String>, locator:Presence<String>, license:Presence<String> }`; `CodeNotice { text:String, locator:Presence<String>, license:Presence<String> }`.
- `ReleaseRecord { id, component:EntityId, distributor:Option<DistributorId>, upstream_revision:Presence<String>, distributor_revision:Presence<String>, captured_at:Presence<String>, time_precision:TimePrecision, schema_version:u32, normalizer:String, normalizer_version:String, captures:Vec<CaptureRef>, assertions:Vec<EntityId>, accounting:ReleaseAccounting, diagnostics:Vec<ReleaseDiagnostic>, selected:bool, availability:Availability, content_notices:Vec<ContentNotice>, redistribution:RedistributionStatus, redistribution_evidence:Vec<String> }`.

Source is obtained via component→collection; capture registry bindings must agree. Available releases require all listed captures/occurrences and complete unique assertion membership: every raw occurrence in their captures maps to exactly one assertion, each assertion belongs to that source, and accounting is Some(actual retained rows/exclusions). Unknown counts are None only for non-Available catalogue data; do not invent zero from absent payloads. Raw repeated observations remain distinct. Multiple releases may refer to the same exact occurrence/assertion; this is membership, not a second observation. Permitted redistribution requires nonempty supplied evidence; Unknown/Held remain valid explicit states, not permission to publish. Code notices are a separate metadata vector.

**Catalogue versus payload:** registry snapshot bindings/release capture refs may outlive loaded raw payloads only when their owning release is explicitly non-Available. Every loaded RawCapture must have a registry binding. A missing raw capture must be named by a non-Available release; it cannot disappear into a successful Available empty result. Assertions/evidence can retain known identities/projections for such a capture, but their raw rows cannot be authenticated while absent; this limit is explicit. A phantom locator under a loaded capture is always an error. This does not change S01 `validate_lexicon`, which retains its complete Lexicon-specific contract. Missing releases may have empty membership and diagnostics; no row count is inferred from unavailable bytes. Every available captured occurrence still has one normalized assertion, including excluded/form-only rows.

### Lexical entries, assertions and contexts

- `PosMapping { value:String, rule:String }` is an explicitly supplied mapping, distinct from native class.
- `EntryRecord { id, source:SourceId, spelling:Presence<String>, language:Presence<String>, script:Presence<String>, native_word_class:Presence<String>, selmaho:Presence<String>, mapped_pos:Presence<PosMapping> }`. Missing spelling is allowed for an explicitly excluded opaque/nonlexical occurrence. Case/apostrophe/dot/y/diphthong/multiword bytes are unchanged. No class/POS is guessed from spelling.
- `Eligibility { Lexical, Excluded { reason:String } }`; no empty exclusion reason.
- `NamedTimestamp { field:String, value:RawJson, precision:TimePrecision }` retains separate supplied epoch/string timestamps.
- `AssertionRecord { id, entry:EntityId, occurrence:OccurrenceRef, native_sense_id:Presence<String>, language:Presence<String>, definition:Presence<TextValue>, source_score:Presence<RawJson>, timestamps:Vec<NamedTimestamp>, eligibility:Eligibility }`. Native entry/assertion IDs and optional contributor remain in existing registry OccurrenceAttribution, referenced through the exact occurrence; do not create competing author/native-ID authority. A definition is not an inferred sense. Assertion occurrence refs are globally unique; different raw locators retain separate IDs even for equal text/native IDs. Entry source agrees with capture source. Lexical assertions require present spelling. Optional source-native sense IDs are retained, never generated from definition text.
- `ContextKind { Gloss, Note, Label, Register, Domain, Example, Translation, Citation }`; `ContextRecord { id, assertion:EntityId, kind:ContextKind, value:Presence<TextValue>, translated_from:Option<EntityId>, evidence:SourceEvidence }`. translated_from must be another context record. Definitions/glosses/notes/examples remain separate; form-only records can have Missing definition and a Gloss context.

### Source frames, forms, etymology and relations

- `ArgumentSlot { order:u32, native_label:String, description:Presence<TextValue>, grammatical_role:Presence<String> }`; `ArgumentFrameRecord { id, assertion:EntityId, slots:Vec<ArgumentSlot>, evidence:SourceEvidence }`. Slot order is explicit/unique per frame; no parser creates frames from prose. Prose farvi four/five witnesses remain separate assertions with no source frame unless the source supplies one.
- `LocalRef { Entry(EntityId), Assertion(EntityId), Form(EntityId), EditorialSense(EntityId) }`; validate the referenced role, not merely global ID existence.
- `OrderedComponent { order:u32, spelling:String, target:Option<LocalRef> }`; unique order, preserve vector order. No rearrangement by spelling.
- `FormKind { SourceVariant, SourcePronunciation, SourceReportedForm, AssignedRafsi, ComputedStem, ComputedComponents, GeneratedCandidate }`.
- `FormRecord { id, entry:EntityId, spelling:String, language:Presence<String>, script:Presence<String>, pronunciation:Presence<TextValue>, kind:FormKind, standing:Presence<String>, components:Vec<OrderedComponent>, evidence:Option<SourceEvidence>, computation:Option<EntityId> }`. Source kinds require source evidence and no computation; computed kinds require a computation run and no claim of source evidence. Source standing is a retained supplied claim, not external certification. Assigned si'e→snime, reported cpan and computed snim stay distinct. Existing Lexicon forms are untouched.
- **Explicit etymology home:** `EtymologyRecord { id, assertion:EntityId, statement:Presence<TextValue>, native_kind:Presence<String>, components:Vec<OrderedComponent>, evidence:SourceEvidence }`. Only source-supplied information is represented here; source null/empty etymology remains distinguishable. There is no etymology inference routine. Additional explicit etymological target links use a source relation with its citation, not a guessed equivalent.
- `RelationKind { SourceSeeAlso, SourceEtymology, EditorialLink, Other(String) }`; `Direction { Forward, Reverse, Bidirectional, Unspecified }`; `RelationScope { Entry, Assertion, Form, Editorial }`.
- `CatalogTarget { source:SourceId, release:EntityId, native_entry_id:Option<String>, native_assertion_id:Option<String>, occurrence:Option<OccurrenceRef> }`; at least one identity is present; source/release must agree. Native IDs are byte-exact, including supplied empty strings. Catalog refs can name unavailable data without physical DB path names.
- `RelationTarget { Local(LocalRef), Catalog(CatalogTarget), Unknown, Unresolved(String) }`; `RelationRecord { id, origin:LocalRef, kind:RelationKind, direction:Direction, scope:RelationScope, target:RelationTarget, evidence:Option<SourceEvidence>, editorial_revision:Option<EntityId> }`. Source relations need evidence and no editorial revision. EditorialLink needs an owned revision and no fabricated source evidence. Unresolved citation is nonempty. Unknown, unresolved, and known-but-unavailable catalogue targets remain distinct; this slice represents them, S04 resolves query-facing states. Do not infer relations from prose outside existing explicitly supplied witnesses.

### Owned history, editorial and computed material

- `OwnedRevisionRecord { id, source:SourceId, parent:Option<EntityId>, editor:ContributorId, timestamp:Presence<String>, time_precision:TimePrecision, assertions:Vec<EntityId>, tombstones:Vec<EntityId>, rationale:Presence<TextValue> }`. Source must be OwnedDraft; parent exists, same source, acyclic. Assertion refs match that source. Tombstones refer to ancestor assertions and are absent from the current full assertion set; old assertions remain in the document. This is an immutable history contract, not production conflict/edit behavior.
- `OwnedHead { source:SourceId, revision:EntityId }`; one head per owned source, matching revision/source. A head's assertion list is the explicitly provided full current fixture set; earlier revisions remain addressable. No default lookup behavior lands until S04.
- `EditorialSenseRecord { id, assertions:Vec<EntityId>, editor:ContributorId, revision:EntityId, rationale:TextValue }`; reviewed explicit grouping only; revision is owned, references all exist, no default suppression or inferred sense per definition.
- `InputRef { Occurrence(OccurrenceRef), Entity(LocalRef), Literal(String) }`; `ComputationRecord { id, tool:String, tool_version:String, inputs:Vec<InputRef>, policy:String, profile:Presence<String>, explanation:Presence<TextValue> }`.
- `ComputedAnnotation { id, computation:EntityId, target:LocalRef, kind:String, value:RawJson, explanation:Presence<TextValue> }`. Tool/run/input/policy and explanations remain separate from source assertions and aesthetic judgment. No tool is run automatically; fixtures supply labelled outputs.
- `ExtensionRecord { owner:EntityId, name:String, value:RawJson, evidence:Option<SourceEvidence> }`; ordered extension rows are retained without flattening JSON. Owner exists. This complements typed fields; it cannot replace required typed schema areas.

`DictionaryMetadata { catalogue_revision:u64, code_notices:Vec<CodeNotice>, collections,components,releases,entries,assertions,contexts,frames,forms,etymologies,relations,owned_revisions,owned_heads,editorial_senses,computations,annotations,extensions }` contains vectors of the corresponding records. Default: revision0 and empty vectors. `DictionaryDocument { version:u32, legacy_archive:Option<Vec<u8>>, registry:SourceRegistry, captures:Vec<RawCapture>, metadata:DictionaryMetadata }`; version1. Default is empty valid version1. Every metadata entity ID is globally unique. References/foreign roles, repeated membership/order, all required provenance, release completeness and catalogue presence validate before constructing Dictionary. No partial mutation exists because Dictionary is immutable. Metadata record order is retained; deterministic JSON for the same document.

### Public entrypoints, error and adapter

`Dictionary::new()/Default`, `from_document(DictionaryDocument)->Result<Self,DictionaryError>`, `document()->DictionaryDocument` clone, `registry()->&SourceRegistry`, `captures()->&[RawCapture]`, `metadata()->&DictionaryMetadata`, `capture(&CaptureRef)->Option<&RawCapture>`, `occurrence(&OccurrenceRef)->Option<&RawOccurrence>`, `to_json_bytes`, `from_json_bytes`, validated serde Deserialize. New JSON helpers reject duplicate envelope/metadata object keys; RawJson/native raw strings remain opaque lexemes. Registry nested strictness is inherited, not bypassed. Version/invalid IDs/JSON/archive/hash/duplicate/reference/provenance/availability/accounting/history errors have matchable named DictionaryError variants (Debug/Display/Error), consistent with existing manual library errors. Use no opaque anyhow/Box errors in public library APIs; no new dependency.

`Dictionary::from_legacy_archive(archive:&[u8], registry:SourceRegistry, metadata:DictionaryMetadata)->Result<Self,DictionaryError>` parses with **existing** Lexicon::from_archive_bytes, checks its registry/capture contract, copies SourceMetadata values/raw bytes/record locators/fields/raw lines through public getters, and keeps the **exact original archive bytes** in legacy_archive. Raw JSON/text encoding follows existing SourceFormat; no source normalization/inference. Caller supplies complete normalized metadata explicitly, using the same occurrence refs; no source/release/sense IDs are guessed. `legacy_archive` validation later replays that exact archive and confirms all its captures/rows/fields equal the corresponding model subset; additional explicitly registered raw captures are allowed without changing old bytes. A generic new document may omit legacy_archive; it is not a silent conversion/rewrite. This adapter plus documented load→explicit metadata→serialize/reload recipe is this slice's migration increment; SQLite rebuild lands in S03.
