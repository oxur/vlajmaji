## Reproduction and evidence

The raw captures, pinned revisions, headers, failures, and offline inspection recipe live in [E02 resource discovery](../experiments/E02-resource-discovery/README.md). Run its manifest verifier and inspector from the repository root. [The complete inventory JSON](../experiments/E02-resource-discovery/derived/inventory.json) retains every matching record and full definition body for the twelve requested headwords plus the constructed absent sentinel. [The population summary](../experiments/E02-resource-discovery/derived/population-summary.json) includes field-presence, duplicate multiplicity, rafsi cardinality, and definition-quality measures. [Negative controls](../experiments/E02-resource-discovery/derived/negative-controls.json) distinguish empty/malformed/truncated/duplicate-key JSON from a valid absence response.

The recipe is Python 3 standard library only, reads captured bytes offline, rejects duplicate JSON object keys before map loading, and preserves all source rows. Whole-population counts describe the entirety of each captured lexical payload; Lensisku API coverage is limited to the twelve requested word routes. It is not a claim of semantic reading or completeness beyond those bounded populations.

The known acquisition day is 2026-10-23. Exact local timestamps for individual requests were not retained. Adjacent HTTP `Date` values are response/cache metadata, not local request times. The manifest distinguishes recorded URLs from source-derived canonical route reconstructions; final redirect URLs remain unknown where they were not captured.

## Twelve-entry witness comparison

Every match and full definition body is preserved in the derived inventory with source locators and fields: La-Lojban by array index, Sutysisku by object key, LLG files by source line, and Lensisku API by response filename plus array index. La-Lojban and Sutysisku each contain all twelve requested entries once; all twelve Lensisku word endpoints returned rows, with multiple definition records for several headwords. The captured LLG gismu file has nine of the nine target roots; cpana is present with a gismu definition but all assigned short-form slots blank. All three non-roots ricrprunu, flaume, and rutrprunu are absent from that file and from the LLG rafsi list. The LLG rafsi file has eight target headwords in nine rows because citno has two assigned forms; cpana is absent from the rafsi form list because it has no assigned short form, not because its root or meaning is absent. Ricrprunu and flaume occur in the English distributions and Lensisku API as fu'ivla. LLG cmavo has no target matches. The constructed PROJECT02_ABSENT_SENTINEL is absent from every captured dictionary/list; Lensisku returned HTTP 404 with body Valsi not found.

The no-duplicate-headword result describes each captured export projection, not absence of upstream alternatives. The Lensisku API sample has two English records each for banro (definition IDs 14688 by brtais and 18 by officialdata), citno (162 by officialdata and 89208 by nalcatni stidi), farvi (69002 by suzil and 333 by officialdata), and kalri (544 by officialdata and 89314 by nalcatni stidi). Their full records and source locators are retained in the inventory. These pairs do not all establish distinct senses: banro differs mainly in formatting, and citno/kalri notes differ. Farvi is a concrete place-count conflict: ID 333 by officialdata mentions four places, while ID 69002 by suzil mentions five, including a reason/event place. This inventory selects no semantic winner. Any later place-data consumer must retain definition identity rather than silently collapse to one place list per headword.

A useful trace is snime:

- LLG gismu line 1121 has the complete place-definition prose “x1 is made of/contains/is a quantity/expanse of snow” and assigned CVV form si'e.
- La-Lojban record definition_id=1053 preserves the English definition, notes and padded rafsi string containing si'e.
- Lensisku’s English record 1053 has the full definition, contributor officialdata, score 100000, and official_rafsi="si'e snim".
- Sutysisku key snime has the same English text and r=["si'e","snim"].

These source-specific projections differ: LLG and La-Lojban show assigned forms, while Lensisku and Sutysisku include an additional four-letter form without a field labeling its status. Do not normalize these into one asserted rafsi inventory. A contrasting witness is cpana: LLG has no assigned rafsi and La-Lojban omits rafsi; Lensisku returns cpan and Sutysisku lists cpan. This shows projection differences, not a malformed La-Lojban record.

For slabu, the English definition has four x-place references in prose, yet La-Lojban omits the place_keywords key and captured Lensisku rows have null place-keyword mappings. No explicit x1/x2 slot labels or ordered argument contract are established in the inspected sources; this inventory does not infer those semantics. Definition prose and optional keyword mappings remain distinct from asserted structured argument slots.

Score, identity, contribution, and vote fields are not correctness proof. Morphological candidates are not dictionary attestations. The two distributions and live API may share upstream data and are not independent confirmations.
- No full current Lensisku export was acquired. Its bounded API observations and the pinned La-Lojban snapshot remain separate.

## Slice02 actual library probes (2026-10-23)

The probe package and exact replays are in [rust-probes](../experiments/E02-resource-discovery/rust-probes/README.md); raw JSONL, stderr, and the offline join are under `experiments/E02-resource-discovery/probes/`. The isolated package compiled on rustc/cargo 1.98.0 with exact crate versions and a separate lockfile. Each forwarded-default and `--no-default-features` run contains 102 rows: 50 generation results, 30 rafsi calls (15 witnesses per engine), eight fixed-input analyses, and 14 distinct candidate spellings analyzed by both libraries. The 78 generation occurrences and 14 unique spellings include map-absent and invalid-letter control outcomes; these counts are not 14 endorsed or usable poetic candidates. Generation, rafsi, and fixed-input analyses agree across modes; exactly two candidate analyses differ, for `flaume'yxrula` and `ricrprunu'yxrula`: default `analyze_lujvo_spelling` returns score-optimal `Some` and `reconstruct_lujvo` succeeds; lean mode returns `None` and reconstruction fails. In both modes `expand_lujvo` and `jvokaha` fail for these strings. Four distinct caller-contract tests pass in each mode (eight executions), covering minimum-score ties on three supported multi-component fixtures, a selected `snime+xrula` expansion/reconstruction witness, visible invalid-letter error class, and missing-map versus implicit-candidate distinction. These tests do not generalize all/best equivalence to empty or single-component cases.

Latkerlo's `get_lujvo_with_analytics` returns one best form plus score and indices; its `grll` exposes candidate forms per component but the inspected public calls do not provide the same complete joined candidate census as vlazba's `jvozba_with` all mode. Its `get_veljvo` and `score_lujvo` worked on the tested ordinary ASCII examples but each panicked on the deliberate `sniméxrula` negative control; the run preserved panic stderr and classified each caught panic. vlazba all mode returned two forms for `snime+xrula` and four for `xrula+snime`, while best-only returned one minimum form for each. Across the supported fixtures tested, best-only was the minimum-score tie projection of all-mode; `flaume+xrula` and `ricrprunu+xrula` had no results in either mode under the pinned default map/options. Forwarding vlazba default features changes the analysis result for exactly two generated spellings, `flaume'yxrula` and `ricrprunu'yxrula`: with defaults, `analyze_lujvo_spelling` returns each as score-optimal; in lean mode it returns `None`. This difference reflects the enabled package feature path, not a change to generation. `zazda` was absent from package root maps and captured dictionaries, but Latkerlo still generated `zazdyxrula`; vlazba generated that form too, and its reverse expansion could not resolve `zazd`. This illustrates why generation is not dictionary attestation. For the invalid-letter `qazda+xrula` case, vlazba emitted `qazdyxrula` (score 10067) in both all and best-only modes; later spelling analysis returned `None` and reconstruction/decomposition failed. Latkerlo rejected the input with `NonLojbanCharacterError`. The emitted spelling is an observed helper result, not a legal-word or poetic candidate claim. On `si'erxrula`, Latkerlo `get_lujvo_with_analytics` reported 9906 while its `score_lujvo` reported 10006; vlazba generation reported 9506. These are observations of different functions and configurations, not interchangeable score scales; no broader scoring diagnosis follows. Empty/single behavior and all-vs-best negative cases remain their own recorded outcomes.

The exact join consumes all 113 records from the captured Lensisku API responses, along with the complete captured La-Lojban (17,056 records) and Sutysisku (23,705 keys) populations. It finds zero exact headword matches for 78 generated occurrences / 14 unique spellings; the 14 include the map-absent `zazdyxrula` and invalid-letter `qazdyxrula` controls and are not a set of endorsed poetic candidates. The join output embeds the 16 English API records, not all 113 API record bodies; all 113 remain in the raw captures and were consumed for exact matching. The derived artifact retains each spelling's producing case/configuration and full matching records/locators, all twelve La/Sut target witnesses, and four English two-record multiplicity pairs without merging definitions. The exact controls `zazda` and `qazda` are absent from both package root maps and both full La/Sut dictionaries (independently checked by CDC); helper outputs still exist, so dictionary/source membership and permitted input class require separate caller checks. “Unattested” is limited to these captures. The API's `place_keywords` remained null for the captured records. No explicit x1/x2 slot labels or ordered argument contract were established in the inspected sources, and `farvi`'s four/five-place conflict remains visible in full records rather than resolved.

The unchanged CLI was rebuilt and returned exit 0 for 15 deduplicated prosody calls (twelve target words and three distinct generated spellings). All nine target roots and the generated forms used caller-declared `gismu-lujvo`; ricrprunu, flaume and rutrprunu used caller-declared `brivla`. Two borrowed forms, `ricrprunu` and `rutrprunu`, produced the existing `syllables.source-length-tension` limitation in the `crpr`/`trpr` consonant sequences; `rutrprunu` is a fruit entry, not a tree. The generated calls expose nuclei and the existing stress/syllabification policies; they do not establish speech realization or word legality.

**Local-research combination for the bounded wordcraft question:** use vlazba as the primary engine for bounded classical-lujvo alternative and reconstruction experiments: its all mode exposes alternatives in the tested cases, and its best-only path matched minimum-score ties on the supported multi-component fixtures. Retain Latkerlo as a guarded comparison for the tested borrowed inputs (including `flaume` and `ricrprunu`) and for its policy-specific single-best outputs; do not use it as a complete alternatives census. Callers must validate permitted input class and source membership before generation and analysis, constrain Latkerlo inputs to its supported character class, and contain the observed panic at the research boundary. The `qazdyxrula` control demonstrates that a generator can emit from an invalid-letter input and that later analysis can reject its own output. This is a local experiment role, not production integration or a general language model.

For data roles, use the pinned La-Lojban snapshot as the local meaning/identity baseline, the bounded Lensisku English records as additional identified alternatives with their multiplicity intact, and the LLG assigned-root/rafsi lists as a separate assigned-form baseline. Use Sutysisku as comparison/projection evidence, not as an independent dictionary vote: the distributions may share upstream content and differ in fields. Keep complete record identity and content notices attached to each source. No inspected resource supplies an explicit ordered argument-slot contract; Lensisku `place_keywords` is null in these captures, and `farvi` retains its four/five-place prose conflict. Thus place data remain an explicit gap, not something to infer from prose. Package-code terms and content reuse terms remain separate; vlazba's GPL-3.0 and the resource-specific source notices require later, separate compatibility and reuse decisions. No project-wide license, production dependency, semantic winner, or universal language/conformance claim follows.
