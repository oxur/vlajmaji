# Lexical model and source-preserving import (Arc02 Slice02)

**CC disposition: proposed-done; all six Slice02 ledger rows remain OPEN for CDC review.** This candidate adds a reusable local Rust library for retaining accepted captured lexical sources, their identities, raw fields and distinct form roles. It is an import/replay boundary for later slices, not a database or production integration. Slice01's current status is independently accepted; its original report history is preserved in [lexical-data-search.md](lexical-data-search.md) and its [closing report](../.worktrees/planning/project02-wordcraft-reconnaissance/arc02-lexical-data-search/slice01-services-standards-contracts/closing-report.md).

## Delivered API and population

[`crates/relojban-lexicon`](../crates/relojban-lexicon/src/lib.rs) exposes `Lexicon`, `SourceMetadata`, `SnapshotIdentity`, `RecordIdentity`, `FieldPresence`, `CapturedRecord`, `FormAssertion`, `SourceCrossReference`, `Proposal`, and typed import errors. `import_source` accepts caller-owned bytes and provenance, computes SHA-256, rejects an optional mismatched expected hash, validates the full source before mutating, and makes the same namespace/hash import explicitly idempotent. `lookup_exact` compares source spelling byte-for-byte and returns every matching row in retained source/language order; proposal lookup is separate. For JSON, `FieldPresence` retains Missing, Null, and raw Value lexemes, including empty values and unknown nested fields. For LLG text, it reports retained decoded/trimmed columns as Value—including literal `null` and blank fixed rafsi columns—while original bytes and lines remain authoritative. Assigned-rafsi rows expose their gloss separately from definition prose. The versioned archive stores original bytes and provenance and rebuilds the derived views through import validation.

The explicit E03 input manifest links to the accepted E02 files by hash. For La, it additionally records the canonical pinned Git repository, commit, repository path and Git blob ID from the E02 manifest; the capture SHA-256 remains separate. The E02 capture timestamp is known only to day precision (`2026-10-23`); its exact acquisition time is unknown and is not inferred from current or fresh-source checks. The example imports all 16 snapshots and writes an archive outside captured inputs. Its generated summary reconciles 21,241 retained rows: 19,696 rows expose definition prose and 1,545 are forms-only assigned-rafsi gloss rows; these are source rows, not distinct senses or unique meanings. The populations are La 17,056; Lensisku 113 from 12 bodies (all language IDs, including 16 English records); LLG gismu 1,436; cmavo 1,091; and rafsi assignment rows 1,545 across 1,196 heads. The 3,091 assigned-form assertions and 1,988 source-reported-form assertions remain separate from record counts. Whitespace-delimited native rafsi strings yield individual exact form tokens for lookup/projection, while the source field retains its complete raw lexeme. No captured payload is duplicated in E03.

Exact `farvi` lookup returns 16 records across the selected population, comprising 13 Lensisku farvi records across languages plus the captured La and LLG rows; source IDs 69002 and 333 both remain in the API population. `si'e` returns the La cmavo/MOI row and the LLG cmavo row; assigned `si'e → snime` remains a separate form assertion; exact `sie` returns no selected rows. The phrase `le jaica` stays a full headword. The bounded v2 “See also” parser requires an explicit marker with non-alphanumeric boundaries, stops at sentence/clause delimiters, ignores braces inside `$...$` math spans, and records UTF-8 byte offsets in decoded notes text. Its regression controls reject `Foresee also {substring}`, `See also $x_{1}$ ...`, and unmarked `{outside}` while retaining genuine marked targets. These source-markup links report no semantic equivalence. The imported corpus is finite and not an exhaustive dictionary.

LLG assignments are `AssignedRafsi`; La/API rafsi strings are `SourceReportedForm`. For example, cpana's `cpan` in Lensisku remains a source report while the captured LLG cpana gismu row has no assigned rafsi; its three known fixed rafsi columns are present as blank Value fields, not Missing and not an assignment. The API's `snim` and `si'e` on snime are not promoted to LLG assignments. Rafsi-list lines expose their gloss separately and do not present that gloss as a definition. Native class, selma'o, definitions, notes, IDs, language fields and all other raw JSON fields remain in each captured record; no UD POS, morphology slot, etymology or winner is inferred.

`Proposal` has no public deserialization path. Archive v2 uses a private proposal wire DTO and validates every row through the public constructor before insertion, returning typed namespace or identity failures. V1 archive proposals are validated with their historical ID encoding and migrated to v2 IDs on the next serialization. Proposal v2 IDs use a domain-separated, length-prefixed SHA-256 encoding, so embedded NULs cannot make distinct field tuples collide by concatenation.

## Optional jbotci probe

The public `jbotci-dictionary` crate at pin `3d9fd41d9ed32de26311ee27ec86b6b165985aa1` built successfully with `--locked -p jbotci-dictionary --features import` in an isolated checkout using stable Rust 1.99.1 and ordinary TLS resolution. This is package-only evidence, not an app, native, model or whole-corpus build. The direct captured La importer call returned `RafsiStandingMismatch` on `bekpi` ID 36701; the captured Lensisku payload returned an unknown-field error on `definitionid`. A copied two-row farvi fixture parsed both IDs and preserved both definitions until optional `retain_best_definition_per_word` was invoked on the copy, dropping one row. The importer projected `fav` from the source `fav`/`farv` pair. Its typed importer maps missing/null notes to empty strings and null/missing/empty selma'o to `None`; separate fixture outcomes are in the runtime log. An extra source field and an unknown native class are rejected by its typed deserializer.

The pinned `places` API segmented actual farvi definitions into five and four typed places. A separate `$x_1=b_1$` alias control resolved notes `$b_1$` to place 1 while `$z_7$` remained an unmapped variable. These are computed text analyses, not source-asserted argument slots. jbotci remains a credible optional import/search baseline, with real multi-row parse, explicit rafsi standing, exact-entry indexing and reusable place segmentation. Its named “exact” query normalizes the query, so it does not implement this crate's source-string contract. The local library does not copy the place parser. Source-code MIT terms are separate from dictionary-content reuse terms; this slice makes no adoption or licensing decision.

## Verification and limits

The outside-workspace consumer at `experiments/E03-lexical-data-search/slice02/probes/external-consumer/` used the public API and only a path dependency on the local crate. It imported the same corpus, checked all farvi rows/language IDs, exact spelling, form/presence access, proposal separation, idempotence and archive reload. After refinement02, the corpus example and external consumer were both rerun under Rust 1.98.0; their summaries report 21,241 rows, 16 snapshots, byte equality for all 16 raw sources after archive reload, 16 all-source farvi rows and 13 Lensisku farvi rows. The regenerated local v2 archive is 28,320,417 bytes (SHA-256 `4e5c30e978bde631349e1107599f3ef9738c1f63257ba280e146d2256c7cef5a`); the separate external-consumer archive is 28,319,503 bytes (SHA-256 `67d5199acea5cc78146df0adff85af1c43d901a01b7dfad1c2079abde8197da9`). Under Rust 1.98.0, all 66 unit/integration tests and 5 doctests pass; formatting, locked workspace check, Clippy with warnings denied and rustdoc with warnings denied also pass. The exact replay commands and observed toolchain are in the slice README and delegated evidence receipt. E02/archive guards and the Project01 source diff are recorded as distinct checks.

The bounded runtime's initial invocation passed the report path instead of the unknown-field fixture and its JSON syntax error was not evidence of rejection. That exact attempt is retained; the correct fixture was then run within the original time cap. Sandbox-only dependency DNS/cache-write failures are also retained separately from the successful ordinary-TLS dependency resolution/build. The refinement02 corpus-example command initially used the output path where the repository root belonged; its failed invocation and the earlier successful log are both retained, and the corrected Rust 1.98.0 rerun is indexed. La capture provenance records the E02-pinned Git repository/revision/path/blob alongside the exact capture SHA; its precise capture time remains unknown within the recorded day-only precision. The pinned source's metadata claim of 33,526 definitions versus 31,248 embedded entries was not independently validated; no full dictionary download was attempted. No runtime or build result implies deployment availability, content rights, a DMLex/OntoLex mapping, persistence behavior, or production suitability.

Downstream persistence should retain source namespace/hash, native upstream ID, locator, all raw bytes and field-presence lexemes, language/class/selma'o, source-reported and assigned form roles, and proposals in a separate origin. Any indexed/normalized/search view should be derived and rebuildable, with its normalization/version explicit; it must not replace the source record or the exact lookup API.
