## Captured evidence

The payload controls use temporary bodies with correct size/hash and matching headers: generic DMLex marker/non-schema JSON, empty JSON, malformed JSON, and a generic ELEXIS challenge page. All eight negative controls reject through the same validator. HTTP headers and original HTML/JSON/source bytes are retained in `raw/`; `derived/` contains replayable indexes, summaries, validation results and provenance records. The broad DMLex visible-text dump has replacement characters for some non-ASCII text: the raw HTML declares ISO-8859-1, while the bounded relevant-section extraction has no replacement characters. Findings use those bounded sections and ASCII protocol/schema anchors; raw bytes remain authoritative, and affected names/examples are not used as evidence.

## Service and standard boundaries

The ELEXIS 1.2 protocol documents dictionary/about/list/lemma and entry fetches, including offset/limit, entry IDs, update `301`, unknown/deleted `404`, and a required service choice among `/json`, `/tei`, or `/ontolex`. Its `/json` example is an ELEXIS-specific shape, not a DMLex serialization. The linked `swagger.json` fetch is preserved as HTTP 404 HTML and explicitly rejected as unusable OpenAPI. The protocol page itself is usable.

The pinned reference code has dictionary, lemma/form, and ID indexes. Its `JsonEntry` has canonical form, one typed JSON POS, optional other forms and morphology/etymology strings, senses with optional definition/reference, and usage. Its POS converter maps to a fixed UD-like enum; arbitrary native classes are not accepted as that enum. The typed JSON struct has no extension map, and `content()` serializes that typed struct; runtime unknown-field retention was not tested. These are source-level findings, not runtime observations.

The exact unmodified build command was `cargo build --manifest-path /tmp/p02a02-elexis-ref/Cargo.toml --target-dir /tmp/p02a02-elexis-target`. Normal-TLS dependency resolution succeeded, locked 183 packages and downloaded dependencies; compilation ended exit 101 with 26 errors, including removed/unavailable `clap::App`/`SubCommand`, Gotham `http_body_util`/`bytes`/`http` and `StaticResponseExtender`, and `rand::thread_rng`. CDC independently reproduced the pinned, unmodified build with `cargo 1.98.0 (797e8a9bc 2026-08-05)` and `rustc 1.98.0 (88d9e12ae 2026-08-18)` using `cargo build --locked --offline`; its log is `/tmp/p02a02-cdc-elexis-build.log`. CC did not rebuild during refinement02. No source patch was made. The one `timeout` command-misuse attempt (exit 127 before Cargo started) and its sole corrected replay are retained separately. Total build/probe time was under one minute. Runtime fixture, pagination, duplicate farvi, `si'e`/`sie`, POS, extension-retention and `otherForm` probes are **not run** because the pinned build failed. The sandbox DNS denial on the first public fetch was followed by a successful ordinary-TLS capture; it is not the build result.

DMLex Core models a monolingual resource: required `langCode` identifies the language of headwords, definitions and examples. Therefore setting `langCode=jbo` while retaining English definitions is not Core-conformant. The Crosslingual Module adds `translationLanguages`, headword translations and `headwordExplanation` (a translation-language explanation rather than a translation). DMLex assumes at most one `headwordExplanation` per translation language in each sense. That does not directly encode all competing source definitions as one sense. Preserve separate source-aware identities/senses or a provenance sidecar; the Relojban → DMLex mapping remains unresolved and no conformance is claimed. DMLex optional entry/sense IDs and Linking relations can carry source IDs and explicit links when the chosen serialization/module and mapping define them; they do not create identity or relations for the source.

OntoLex is a vocabulary for grounding lexical material in an ontology, not a source of ontological truth. `subterm` links related lexical entries but does not identify the realized inflected form or its position. Components represent a fixed list; explicit RDF membership/order properties such as `rdf:_1`, `rdf:_2` are needed to preserve order. `vartrans` offers entry/sense relation structures, but an actual source-backed relation and direction must exist before emitting one. No Relojban etymology or semantic relation is inferred here.

Native Lojban class, selma'o, assigned rafsi and experimental rafsi are retained as source-native data. A free controlled tag or ELEXIS `other` POS does not establish equivalence to UD POS. DMLex controlled part-of-speech tags can carry a documented label but do not magically normalize the native inventory. Rafsi standing/assignment needs an explicit typed mapping or extension/sidecar rather than an unreviewed inflected-form or etymology claim. Code licenses and dictionary/content terms remain separate; no license conclusion is made for the project.

## E02 replay and observed discriminators

`probes/replay_e02_witnesses.py` imports only the accepted E02 reader functions and writes into E03. It reproduces all 12 target La raw records and all 16 English Lensisku records (`langid=2`) from the 12 captured word responses. Full bodies remain in E02, and the derived file gives each array/file index, source definition ID, language/class and selected field names. In particular, both Lensisku `farvi` IDs 333 and 69002 remain visible alongside La ID333; their place counts differ four vs five. This finite sample does not imply full Lensisku coverage.

The same replay projects La records from their actual `definition` field and records optional-field state (`absent`, `null`, `empty`, or `present`) rather than fabricating a null `meaning` field. It keeps La `si'e` ID2171 (`cmavo`, `MOI`) separate from the LLG cmavo `si'e` row and LLG's assigned `si'e → snime` rafsi row. `sie` remains a distinct exact spelling and is absent in the captured La/LLG source-field lookups; do not reuse jbotci’s normalized query as evidence of exact spelling absence. LLG `cpana` has no assigned short form in its row; a predictable form or a Lensisku projection is not an assignment. LLG's fixed-width word field preserves the multiword control `le jaica`; whitespace-first-token parsing would lose it.

## Slice01 decision for the later model

Carry exact source identity and language per record; preserve every captured alternative and original locator; model native class/selma'o apart from UD POS; retain rafsi with source, standing and assignment status; represent ordered components only when an ordered parse supplies them; and leave missing places, etymology and semantic relations unknown. Treat standards as optional interchange adapters with explicit mapping/loss records. Do not use a standard or service representation as the local source-of-truth model. The finite Q01–Q06 inputs, outputs, witnesses, downstream owners and unknown policy are in [research/lexical-query-contract.md](lexical-query-contract.md).
