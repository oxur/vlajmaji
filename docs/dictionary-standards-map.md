### Language and cardinality constraints

DMLex Core §3 describes monolingual resources, while this fixture has Lojban headwords and English definitions. A candidate DMLex mapping therefore needs its Crosslingual module's translation-language explanation and resource translation-language members, not a core-only `langCode=jbo` claim. DMLex limits explanations per language per sense; multiple farvi alternatives still need distinct source-aware assertion/sense identities, an explicit extension, or a documented unresolved mapping. No exporter selects among these options in S02.

OntoLex/DMLex vocabulary names in this document describe candidate correspondence only. A populated Rust field is not proof that a standards graph has the same identity, language, cardinality, or provenance semantics.
