# Versioned dictionary model (S02)

`vlajmaji_lexicon::Dictionary` is an immutable validated envelope over exact captured bytes, occurrence rows, source registry bindings, and explicitly supplied normalized metadata. It is not a parser, RDF exporter, database, query API, or automatic linguistic analysis. The version-1 JSON format is deterministic for the same document; loading through `Dictionary::from_json_bytes` rejects duplicate envelope keys and revalidates all typed references. Unknown fields in typed records are errors. Opaque native and extension JSON is stored as a validated raw JSON string so nested keys, large numbers, and source spelling are not reconstructed through a generic JSON value.

## Presence, identity, and raw data

`Presence<T>` distinguishes an absent field, explicit null, and a supplied value (including empty text). `TextValue` carries text, optional language, and optional markup independently. `EntityId` uses the same lowercase ASCII identifier grammar as the source registry; it is not a source ID, a native upstream identifier, or a content hash. `CaptureRef` is the exact `(namespace, sha256)` snapshot identity. `OccurrenceRef` adds the exact legacy locator. The store's `record_id` remains the lowercase-hex encoding of the complete length-prefixed tuple bytes; it is not used or redefined by this model.

A `RawCapture` contains original bytes and ordered `RawOccurrence` rows. `NativeField` retains repeated names and exact JSON lexemes or decoded text values; absent, null, empty string, and literal text `null` remain distinct. An unsupported row can be retained as opaque bytes with an explicit excluded assertion, without weakening the existing La/Lensisku/LLG parser. A dictionary accepts captures only when their identity SHA-256 matches the supplied bytes. The constructor for a draft does not validate registry membership or the rest of the document.

The legacy adapter is explicit: parse an accepted archive with the existing `Lexicon::from_archive_bytes`, provide a complete registry and normalized metadata, then call `Dictionary::from_legacy_archive`. The adapter preserves exact archive bytes, source bytes, snapshot tuple, locators, field lexemes, and text lines. Reload validates the legacy subset against those bytes; additional new-format captures can coexist. It does not rewrite v1/v2 archives or invent entry, source, language, sense, frame, etymology, or POS identities.

## Catalogue and assertions

Catalogue `CollectionRecord`, `ComponentRecord`, and `ReleaseRecord` describe source/release availability independently from loaded `RawCapture` payloads. Available releases require loaded captures, complete occurrence-to-assertion membership, and observed `Some` counts. `Missing`, `Disabled`, and `Removed` releases can retain known references with unknown `None` counts; a missing payload is never counted as an empty available dictionary. A loaded occurrence always has one normalized assertion, including form-only and excluded rows.

`EntryRecord` retains exact spelling, language, script, native class, selma'o, and an explicit optional POS mapping separately. `AssertionRecord` preserves one source observation, its native sense ID, language, definition, score, timestamps, and eligibility. Equal text or native IDs do not merge observations. `ContextRecord` keeps gloss, note, label, register, domain, example, translation, and citation distinct. `ArgumentFrameRecord` exists only when a source supplies a structured frame; prose is not parsed into places. `FormRecord` separates source-reported forms and assigned rafsi from computed stems/components/candidates. `EtymologyRecord` is source-asserted only and distinguishes missing/null/empty statements. `RelationRecord` keeps local, catalogue, unknown, and unresolved targets separate.

Owned revisions are an immutable history record. `OwnedHead` selects one explicitly authored full assertion set; prior revisions remain addressable, and tombstones refer to prior assertions without deleting them. Editorial senses are explicit reviewed groupings. `ComputationRecord` and `ComputedAnnotation` retain tool, version, inputs, policy, profile, and explanation separately from source assertions. `ExtensionRecord` retains typed-owner extension JSON without replacing required fields. Content notices/redistribution and code notices are separate metadata.

Evidence refers to an exact occurrence and optional ordered field index. Text offsets are checked against decoded UTF-8 text/string fields when present. For catalogue-only absent data, the validator can check the known reference and range ordering, but cannot authenticate unavailable bytes or verify a missing field's bounds.

## S02 fixture and migration example

`examples/dictionary_fixture.rs OUTPUT.json` writes only to a fresh explicit path, reloads the complete JSON, and checks the whole document. The shared public helper includes 9 captures and 20 occurrences (19 accepted-legacy rows plus one opaque excluded row), 14 entries, 20 assertions, and populated typed areas. Its data is synthetic except the explicitly cited small pinned farvi and LLG cpana witness material; the example is not a corpus import. The focused contract suite checks complete document equality and selected failure classes. S03 adds relational persistence; S04 owns grouped lookup behavior.


Validation errors are typed: DuplicateEntity identifies a repeated model identity; MissingReference identifies a dangling or wrong-role target; InvalidAccounting covers release membership/count mismatches; InvalidAvailability covers impossible payload/status combinations; InvalidProvenance covers source/computed evidence conflicts; and InvalidHistory covers invalid owned revision ancestry or tombstones. InvalidDocument is reserved for structural constraints without a more specific category. Malformed input is rejected as a Result; the public constructors do not rely on panics for untrusted document state.
